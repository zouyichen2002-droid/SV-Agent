## 1. 结论先说

```
  PRD 目标：热启动 20 次里至少 19 次 ≤ 30 秒

  gm.dls 采样钢琴  ▏ 0.23 秒   20/20 ✓   ← 推荐
  代码合成钢琴     ▎ 1.22 秒   20/20 ✓
                   0 ──────────────────────────────── 30 秒
                   └ 渲染只占预算的 0.8% ┘
```

**渲染不是瓶颈。** 30 秒预算几乎全部留给了模型生成（PRD §8.1 ②）和进程间通信。

这带来一个直接的设计推论：**候选一生成就顺手预渲染**。
这样「点击试听」只剩下播放一个现成的文件，是瞬间的 —— 比 30 秒的目标还快得多。

## 4. 测量结果

| | gm.dls 采样钢琴 | 代码合成钢琴 |
|---|---|---|
| 载入音源 | 0.002 秒 | 0（没东西要载入） |
| **热启动**（常驻进程 × 20） | 中位 **0.233** · 最慢 0.258 秒 | 中位 **1.220** · 最慢 1.262 秒 |
| ≤ 30 秒 | **20 / 20** | **20 / 20** |
| 比实时快多少 | 218 倍 | 42 倍 |
| **冷启动**（新进程 × 5） | 中位 0.470 · 最慢 0.476 秒 | 中位 1.520 · 最慢 1.547 秒 |
| 失败 | **0** | **0** |
| 峰值 / RMS | −2.8 / −20.0 dBFS | −4.3 / −20.0 dBFS |
| 削波样本 | 0 | 0 |
| 两次渲染逐样本相同 | 是 | 是 |
| **音准**（见第 5 节） | 绿 · 最大偏差 4.2 音分 | 绿 · 最大偏差 0.3 音分 |

**「两次渲染逐样本相同」为什么要测**：A/B 比较公平的前提（PRD R05「相同预览音色和增益」）。
如果同一份音符两次渲染出来不一样，你听出的差别就可能是渲染器自己的抖动，不是两个候选的差别。

**增益是固定的，不做逐文件归一化**：同样是 R05 —— 逐文件归一化会让两个候选响度各不相同。

## 5. 音准：第一版检查报了一个假红

「能播」不等于「音准对」。gm.dls 的基准音、微调、采样率换算里任何一处写错，
旋律都会整体跑调、移调或差八度 —— **文件照样能播**，你也未必第一耳就听出来。
所以加了音准检查：28 个测试音（覆盖样本用到的全部音区，外加 gm.dls 每两个分区的交界处）。

### 第一版：YIN 判 gm.dls 红

```
  YIN（按波形周期性测音高）
  键 60–67 整个分区 +11.2 音分   ← 旋律主要就在这个音区
  键  0–38           +17.2 音分
  误差在每个分区内是常数，恰好在分区交界处跳变
```

「分区内是常数」说明换算公式没错（错的话误差会随离基准音的距离而变），
看起来像是**采样本身的音准偏高**。

### 换一种独立测法，结论翻过来了

```
                 YIN        FFT 基频谱线
  代码合成钢琴   +1.5～+7.0   ≤ 0.3        ← 基频是按公式精确生成的，FFT 才是对的
  gm.dls 60–67   +11.2        −0.5
  gm.dls  0–38   +17.2        −3.5
  gm.dls 其余    +0.5～+14.5  −0.3～+0.0
```

**gm.dls 的音准没问题，偏的是 YIN 这个检查器。** 真钢琴的弦是非谐的 ——
高泛音比整数倍略高；YIN 看整个波形的周期性，会被这些偏高的泛音往上拽。
代码合成钢琴上同样看得到这个偏置，而那边的基频是精确已知的。

**如果只信第一版检查，就会去「修」一个不存在的音准问题。**
这和 v1 那个 +11 ms 的起音检测偏置是同一类错 —— 让你去修测量误差。

### 现在的检查：两级，而且证明过会响

| 级 | 方法 | 容差 | 抓什么 |
|---|---|---|---|
| 粗查 | YIN，搜索范围放宽到 ÷2.2～×2.2 | ±50 音分 | 移调、差八度 |
| 细查 | FFT 基频谱线，抛物线插值 | ±10 音分 | 整体跑调 |

粗查的范围必须放宽：太窄的话，差八度的错误会被当成「在范围内找到了次谐波」，**反而报绿**。

注入三个故意写错的渲染器，都必须全部报红（PRD §12 纪律一：只报绿的检查不算检查）：

| 注入的缺陷 | 报红 | 测到的误差中位 | 预期 |
|---|---|---|---|
| 基准音偏一个半音 | 28 / 28 | −94.2 音分（粗查） | −100 |
| 忘了采样率换算 | 28 / 28 | +1204.4 音分（粗查） | +1200 |
| 整体偏高 15 音分 | 28 / 28 | +14.7 音分（细查；粗查会放过它） | +15 |

第一行的 −94.2 不是 −100，差的 5.8 音分正好是 YIN 在真采样上的平均偏置 —— 又一次对上了。

复现：

```bash
cd /e/sv-bridge/spikes/m0-01-piano-preview && python pitch_check.py
```
