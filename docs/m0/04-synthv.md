## 3. SynthV 会改结构 —— 裁判 1 错在这里

```
  我写的                                  SynthV 打开后（恢复文件里）
  轨道「M0 测试」                         轨道「M0 测试」
    └ 主音符组 main：8 个音                 ├ 主音符组 main：0 个音   ← 第 1 版脚本只读这里
                                            └ 引用（偏移 0）─► 音符库组「M0 测试 1」：8 个音
```

你截图里编排区那个色块叫「M0 测试 1」，就是这个新建的组。时间偏移是 0，所以听起来完全一样。

**对 v2 的影响：**

| | 要怎么做 |
|---|---|
| 读 `.svp` | **必须读全部音符组**（主组 + 轨道引用的音符库组），位置按「本地起点 + 引用偏移」换算。导出脚本第 2 版和 `verify_recovery.py` 已经这样做 |
| 写 `.svp` | 考虑**直接按 SynthV 自己的结构写**（音符放进音符库组，轨道引用它），这样 SynthV 就不用改结构，你存盘后的文件和我们写的也更接近 —— 手改检测（PRD R09）会更准。**待验证** |
| 为什么会挪 | **没查清。** 你 8 月的一些恢复文件里，音符就在主音符组里、没被挪。只有这一个样本，不下结论 |

## 4. 人声导出只能你手点（一手依据）

```
               能不能打开工程   能不能保存   能不能导出音频
  FL 命令行    ✓               ——          ✓        （M0-03）
  SynthV 脚本  ✗               ✗           ✗        ← 官方脚本手册一手确认
  SynthV 界面  ✓               ✓           ✓        只能手点「导出为文件」
```

- **官方脚本手册** <https://resource.dreamtonics.com/scripting/>：`Project` 类 21 个方法、宿主对象 `SV` 的全部方法里，
  都没有打开、保存、渲染、导出；唯一和文件有关的是 `getFileName()`（读当前路径）
- **官方用户手册「渲染与导出」**：导出是渲染面板里的 **[导出为文件]**，没有提到命令行、批量或脚本导出
- 旁证：上游桥 0.3.1 把 *「project save and audio render/export」* 列为官方接口缺失的能力

**把这一下压到最小**：导出设置存在 `.svp` 的 `renderConfig` 里，我们生成工程时预填好；
实测 SynthV 原样接受（恢复文件里就是预填的值），导出文件落在了预设位置。
SynthV 会在文件名后面加 `_MixDown`（手册：「输出文件名会在你指定的名字后加上音轨名或 MixDown」）。

**手册一处错误**：中文手册说渲染面板是「启动栏从上数第四个图标」，英文手册说第五个。
你的截图证实是**第五个**（fx 下面那个托盘加向上箭头的图标）。

## 5. `.svp` 的结构（读的是 SynthV 自己存的文件）

| 项 | 结果 |
|---|---|
| 格式 | 纯 JSON（SV1 的文件末尾有个 NUL 字节，SV2 没有） |
| `version` | **196**（空模板、你最近的工程、这次 SynthV 存的恢复文件都是） |
| 顶层 | `version` · `uuid` · `time` · `library` · `tracks` · `renderConfig` · `projectMixer` |
| 速度 | `time.tempo = [{position, bpm}]` —— 比 FL 直白得多，直接是 BPM |
| 时间单位 | blick：1 个四分音符 = 705,600,000 blick。起点和时值都是整数 |
| 音符字段 | 11 个；366 个真音符的默认值完全一致（`singing` · 空重音 · `{evenSyllableDuration: true, muted: false}` · 同一个 takes） |
| 导出设置 | `renderConfig`：输出文件夹、文件名、声道、位深、采样率等 |
