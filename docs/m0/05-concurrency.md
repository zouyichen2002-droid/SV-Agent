## 1. 结论先说

```
  问题                                   SynthV                    FL
  ① 外面改了文件，软件会不会发现？         不会，没有任何提示          不会，没有任何提示
  ② 你一保存，外面的改动还在不在？         没了 —— 整个覆盖            没了 —— 整个覆盖
  ③ 软件开着时，命令行导出另一个工程       ——（SynthV 没有命令行）     失败：第二个 FL 0.8 秒异常退出，不出文件
                                                                     你开着的那个 FL 不受影响
```

## 2. 这对 v2 意味着什么（按铁律）

| 规矩 | 为什么 |
|---|---|
| **永远不在后台改写你可能开着的工程**，一律写新文件 | ① ②：否则你一保存，我的改动就静悄悄没了 —— 或者反过来，我写盘的时候把你没保存的内容顶掉 |
| **发现你改过**（文件哈希变了）→ 当作你的新版本导入，不覆盖 | PRD R09 手改保护。这次两个软件存盘后文件都变了，哈希能看出来 |
| **自动导出之前先看 FL 开没开**：开着就不导，提示你关掉 FL，或者改成你手动导出 | ③：开着的时候导出会失败 |
| 调 FL 命令行**一律检查产物** | 这次失败的退出码不是 0，看得出来；但 M0-03 里 `/M<文件夹>` 的退出码是 0、却什么都没导出 |

### 4.2 FL 开着时用命令行导出（全自动，测了两次）

那一轮的监视程序在 15:48:00 导出时，记下的「FL 进程列表」是**空的**，导出却 4.1 秒就成功了。
进程列表为空，最可能的原因是你存完就关了 FL —— 导出那一刻 FL 本来就不在（**没有证实**）。
那个数据说明不了「FL 开着时」的情况，所以单独做了一个全自动的探针，**先证明它看得见 FL，再下结论**：

```
  打开 FL（flp_open.flp）→ 2.9 秒后窗口标题出现「flp_open.flp - FL Studio 2025」   ← 探针看得见 FL
  命令行导出 flp_render.flp，全程每 0.3 秒记一次所有 FL 进程和窗口标题
```

| | 第 1 次 | 第 2 次 |
|---|---|---|
| 冒出第二个 FL 进程 | 是 | 是 |
| 它怎么结束的 | **0.8 秒后异常退出**，状态码 `0xC0000602`（Windows 的「快速失败」异常） | 同左 |
