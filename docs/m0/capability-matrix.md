**37 条：绿 20 · 红 4 · 灰 12 · 不做 1**（明细见第 3 节）。

**红的四条都有替代路径**：人声导出 → 你点一下；FL 开着时导出 → 先关 FL，或你手动导出；
后台改写你开着的工程 → 一律写新文件；basic-pitch → 两条退路（V2 再验）。

**M0 测的是「管道」，不是「出歌」。** 生成歌词和旋律一条都没测过 —— PRD §14 的七项风险里没有这一项，
但 V1 离不开它。它是 M2 的第一个风险（见 [V1 清单](v1-list.md)）。

## 4. 灰的什么时候验

每一条都要**两个互相独立的裁判**对上才算绿 —— M0 里检查器自己错了三次（YIN 的音准偏置、只读主音符组的导出脚本、被错位骗过的 `.flp` 结构检查），都是第二个裁判抓到的。

| 灰 | 什么时候 | 两个裁判 |
|---|---|---|
| 生成歌词、旋律和声节奏 | **M2 一开始** | 结构检查器 + **你的耳朵**（PRD §8.2：好不好听只能你判） |
| 主进程 ↔ worker 通信 | M2 | 往返耗时计入 PRD §8.1 ①，失败也要计数 |
| 写 MIDI 文件 | M2 | 你在 FL 或 SynthV 里导入一次，和我们写的逐个音比（FL 手册列的命令行参数里没有导入 MIDI） |
| 写音符、配器进 `.flp` | V1.1 之前 | FL 自己导出的 MIDI + WAV（M0-03 的做法） |
| SynthV 按 48 kHz 导出 · FL 导出的格式和采样率 | V1.1 | 改设置后导出，ffprobe 读采样率 |
| 按 SynthV 自己的结构写 `.svp` · 整曲规模 · 调教参数 | V1.1 | 恢复文件 + 导出的 WAV（M0-04 的做法） |
| 你的真工程（第三方插件）能不能命令行导出 | 用第一个真工程时 | 产物在不在 + 时长对不对 |
| 从 `.svp` 生成 SRT / LRC | V1.1（M4） | 和 SynthV 里的音符时间逐句比 |
| 恢复文件多久写一次 | 需要时 | —— |
| B站封面规格 · 网易云 4 项 | 发布时，你看页面 | 页面上写的 |
| CUDA 版 torch · basic-pitch 的退路 · audio2score | V2 选方法时 | —— |
