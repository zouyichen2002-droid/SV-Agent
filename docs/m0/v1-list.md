## 1. 结论先说

```
  R01–R14 没有一条被 M0 否掉。M0 改的是「怎么做」，不是「做不做」：
    R04 快速试听                  候选一生成就预渲染 → 点「试听」只是播放现成文件
    R05 A/B                       同一份音符逐字节相同 → 听出的差别只可能来自候选本身
    R09 手改保护                  两个软件都会静悄悄覆盖 → 永远写新文件
    R12 导出                      MIDI 要读回来核对一次 · ★ 建议加 .svp 导出

  V1 最大的未知不在 M0 的范围里：
    R02 歌词 · R03 旋律和声节奏   生成一条都没测过 → M2 的第一个风险
```

**按铁律**（PRD §0），V1 能不能让出歌更好、更快，取决于 R03 生成的旋律你愿不愿意继续做 ——
M0 验证的全是它周围的管道。所以 M2 的第一步是一个**最小生成探针**，你听过再往下搭。

## 3. ★ 要你拍板或给信息

### ★1 R12 要不要加 `.svp` 导出 —— 我建议加

| | |
|---|---|
| 现在 | R12 只导 MIDI 和试听 WAV。你想在 SynthV 里听它唱，得导入 MIDI、再一个字一个字填歌词 |
| 加了之后 | 候选直接存成 `.svp`（带歌词、声库），你在 SynthV 里打开就能唱。导出人声仍然是你点一下（M0-04 的硬限制） |
| 为什么现在能加 | 写 `.svp` 在 M0-04 已经绿：速度、拍号、音符、歌词、声库逐个精确一致 |
| 按铁律 | **更快**：省掉导入 MIDI 和填歌词。**更好**：发音、咬字、词曲贴不贴，钢琴听不出来（PRD §8.1），SynthV 唱出来才听得出 |
| 代价 | V1 多一种导出格式；每次写新文件（M0-05）。**你在 SynthV 里改完、我读回来当新版本 —— 这一半建议先不做**：要把你改过的音对上原来的稳定 ID，这件事没做过，放到 P1 那一批 |
| 要顺手验的 | M0-04 只测了 8 个音。V1 片段的旋律大概几十到一百多个音，第一次导出时用恢复文件逐个核对（M0-04 的做法）。调教参数不在 V1，不碰 |

### ★2 生成用哪个模型（R02、R03）

PRD §17.2 要开工前确定「可用模型」。**需要你告诉我你手上能用哪些** ——
比如你现在用的 Claude，或者你已经有的其他模型接口。
这牵涉费用和账号，由你定。M2 的最小生成探针会拿你给的几个各试一次，**你听过再定用哪个**。

### ★3 单任务预算上限

T12（预算不足时暂停）要一个数。PRD §17.2。**给个大概就行**（比如一次生成最多花多少钱），以后随时改。

### ★4 每周能投入多少时间

PRD §15：M0 完成后，按每周可投入的时间估算 M1–M3。**你给个大概**，
我按它把 M1 切成你读得完的小批次（纪律四）。

### ★5 冷启动的目标（PRD §8.1 ③ 写的是「V0 后才确定」）

建议：**试听链路冷启动 ≤ 3 秒**。依据：worker 环境实测冷启动中位 0.67 秒（M0-02，5 次，658–692 ms），
留 4 倍多的余量；真正刚开机、文件缓存全冷的情况没测。
生成模型的加载时间**不算在内** —— 模型还没定（★2），定了再补。

## 6. V1 怎么算做完

**不变，以 PRD 为准**：§8.1 试听性能 · §8.2 至少 5 个创作意图里有 3 个你愿意继续做 ·
§16 的 T01–T08、T10–T12（T09 随 R13）。

这两样 M2 测。
