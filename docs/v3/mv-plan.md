# 代表作 MV 计划：每首歌单独定概念、写专属场景（照 pdoom-video 的做法）

你 10-03 定：做「大的」—— 每首约一周，每首歌单独定概念、写专属场景，在 Claude Code 里一起做；只给想做成代表作的那几首。
**现在不急**：你在找要翻唱的好歌，先要一份计划。

参考：[mexicat/pdoom-video](https://github.com/mexicat/pdoom-video)（MIT），B 站转载 BV18ta86EEHb。拆解见 §6。

## 1. 做出来是什么样

- **成片**：1080p60（最好的几首出 4K），用代码一帧一帧画出来
  - 歌词就是画面：被写出来、刻出来、织进去、盖上去…… 不是叠在上面的字幕，每个字按唱的时间亮
  - 每首一个总概念 + 一条贯穿全片的线索
  - 一套设计：配色、字体、颗粒
  - 几个到十几个场景，一段一种画风，但看起来是一个整体
  - 换镜头落在强拍，冲击落在鼓点；60 帧 + 运动模糊 + 泛光、颗粒
- **另外出**：
  - 设计手册 `TREATMENT.md`：概念、风格、场景表
  - 封面
  - B 站发布信息

## 2. 一次性的准备（第一首之前，约 2–3 天；你找歌的时候就能做）

| 件 | 做什么 |
|---|---|
| 渲染引擎 | 从 pdoom-video 拿**引擎部分**：时间线、后期（泛光 / 光晕 / 颗粒 / 运动模糊）、字体排版、线条、合成、导出脚本。去掉它的歌和场景，放进我们仓库的 `mv/`，保留它的许可声明 |
| 接我们的数据 | ① 逐字时间：直接从你最后改完的 SV 工程出，就是现在做字幕用的那套，比它的强制对齐准 → 转成它要的 `lyrics.json`。② 拍子、强拍、段落：用找拍子的结果。③ 鼓点（底鼓、军鼓、镲）、各分轨响度：用已有的分离结果再算。②③ 转成 `audio.json` |
| 中文、日文排版 | 可变粗细的中文、日文字体（长音加粗、紧张时变细）；逐字（我们本来就是逐字）；可以竖排。另一个能做的亮点：用笔顺数据让「笔一笔一笔写出汉字 / 假名」（Make Me a Hanzi、KanjiVG；许可要先查清楚） |
| 本机渲染 | 后台 Chrome 逐帧画 + ffmpeg 编码。这台笔记本有两块显卡（AMD 核显 + RTX 5070 Ti），要确认 Chrome 用的是 RTX。测一下 1080p60 一首要多久（pdoom 的 4K 在 M5 Pro 上 2.5 小时） |
| 看片的办法 | 出单帧、联系表（一个场景十几帧拼一张）、几秒的短片段：你看图给意见，我看图自查 |
| 练手 | 用《怪物》做一两个场景的样片，确认整条路通了 |

**要你点头的下载**（到时候逐项列准）：
- npm 包：three.js、vite、playwright-core 等，估计一百 MB 以内
- 中文、日文字体：OFL 许可，每套十几到几十 MB
- 笔顺数据
- 不用装 bun，用本机的 Node 24

## 3. 每首歌（约一周）

| 天 | 做什么 | 你做什么 |
|---|---|---|
| 第 0 步（就是平时的翻唱） | DSH 里翻唱出工程 | 在 SV 里调、混音、导出成品音频。MV 的概念可以和调音同时开始；歌词时间以你最后改完的工程为准 |
| 第 1 天：概念 | 一起听歌、读歌词（意思、意象、情绪走向），定这些东西，写成设计手册：总概念、贯穿线索、配色、字体、场景表（每段歌词用什么画风、表达什么）、「不要什么」清单 | 定概念、点头 |
| 第 2 天：粗剪 | 时间线：场景按歌词句子分段，对齐强拍。每个场景先放占位（字 + 拍子闪），出低清预览看节奏 | 看节奏对不对 |
| 第 3–5 天：场景 | 一个个写场景；可以几个 Claude 分工同时写（pdoom 就是这样），我当组长统一风格。每天给你看单帧、联系表、短片段 | 每天看、说哪里改 |
| 第 6 天：打磨 | 转场、后期、字距、歌词可读、安全区；4K 试一段 | 看整片 |
| 第 7 天：出片 | 正式渲染（几小时，低优先级、夜里跑）→ 检查 → 封面 → 发 B 站 | 最后点头、发布 |

## 4. 选歌（你在找歌，供参考）

适合做代表作的歌：
- **翻唱效果好**：主唱清楚，叠唱 / 合唱少，不是大段戏腔或说唱。《逃跑的天使》这类是我们目前做得最好的
- **有画面感**：歌词有具体的意象或故事，能做「视觉双关」，不只是抒情
- **起伏大**：主歌、副歌、间奏、高潮分得清，鼓点清楚。画面靠这些落点
- 长度 2.5–4 分钟，速度稳定或分段清楚
- 你特别喜欢、愿意花一周的

## 5. 规矩和风险

- **原创**：画面不抄原 MV、不画已有的角色；署原唱、作词作曲
- **授权**：发布别人的歌前由你确认；B 站选「含AI生成内容」
- **机器**：渲染吃显卡，要几小时。渲染时让出本地模型；你要用电脑时可以停、再接着渲
- **在哪做**：这件事在 Claude Code 里做，本地模型写不了这种代码。DSH 还是只管翻唱和普通歌词视频
- **一周是估计**：第一首会更久，要边做边补引擎；熟了以后会快

## 6. pdoom-video 是怎么做的（10-03 读它的仓库）

- 网页程序（TypeScript + three.js / WebGL）：每一帧是「歌曲时间」的函数；浏览器里实时预览，导出时后台 Chrome 逐帧画、ffmpeg 编码
- 前期数据：
  - 分离：Demucs + 和我们同一个主唱 karaoke 模型
  - 逐词对齐：强制对齐 + Whisper 交叉核对
  - 节奏：拍子、强拍、段落、鼓点、各分轨响度
- 设计手册：
  - 总概念是「一本讲世界末日的插图论文」，17 个场景各一种画风（铜版画、示波器、公文纸、钞票花纹、蓝图、3D、织物、界面）
  - 只有墨黑、骨白、一种橙色（外加一个只出现约 2 秒的酸性绿）；一根橙色火花贯穿全片
  - 「反俗套」清单：不要霓虹赛博、发光大脑、代码雨、粒子星云
- 后期：
  - 60 帧，每帧最多平均 324 个子帧，做出真正的运动模糊
  - 只有橙色会泛光，再加光晕、胶片颗粒
- 规模：场景代码 40 个文件、将近 1 MB；文档是写给「场景作者 A1–A8 和组长」的；作者说全程和 Claude（Opus 5.5）在 Claude Code 里做
