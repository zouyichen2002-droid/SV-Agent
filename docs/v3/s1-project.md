## 1. 你定的两件事（10-01）

| 问题 | 你选的 |
|---|---|
| 「一首歌」在 DSH 里怎么放 | **一首歌一个工作区**：每首一个文件夹 `E:\sv-agent-workspace\<歌名>\`，侧栏里一首一组；沙箱只许写这首歌的文件夹 |
| 做过的 5 首要不要建成项目 | **建成项目**：原来的探针文件留在原处、只读引用，不搬不复制 |

这正好是 DSH 自己的设计：它的工作区服务（`dsh-workspace`）本来就管这些目录叫「项目」，插件调 `ctx.workspaceRegistry.create(目录, 名字)` 就能让一个文件夹出现在侧栏。

## 2. 做了什么

```
 E:\sv-agent-workspace\            ← 大厅（不属于任何一首歌）
   ├─ 傍晚\sv-project.json          ← 每首歌一个文件夹 = DSH 侧栏里的一组
   ├─ 潮声回响\sv-project.json
   ├─ 刽子手\sv-project.json
   ├─ 逃跑的天使\sv-project.json
   ├─ 天星问\sv-project.json
   └─ _弃用_阶段0测试\              ← 阶段 0 的测试小文件挪进来（不删）；「_」开头的不算项目

 sv-project 插件（DSH 进程里）
   ① 每一步：在运行时上下文里放一小段「当前项目」—— 歌名、类型、可写文件夹、状态、外部素材、项目里每类文件几个、最新工程
      （大厅里：列出有哪些项目）
   ② 工具：project_list · project_status · project_create（新建 / 认领 → 登记到侧栏）· project_update（状态、来源、备注）
```

- 「当前项目」= 会话的工作目录（往上找 `sv-project.json`，到项目根为止）—— 不用自己从会话日志里推，DSH 本来就把会话的工作目录定死在会话里
- 每一步那一小段放在**运行时上下文**里（`ctx.systemPrompt.context`）：追加在历史后面、不碰系统提示词 → 模型服务的缓存前缀不作废；内容没变时一字不差，DSH 就不重复追加
- 5 首的 `sv-project.json` 内容全部来自 `docs/m1/station-end.md` 和各首探针里的 `source.json`：来源、拍子、最后一版、你的评价、遗留；外部素材 20 处路径建之前逐个核对过都在
- 插件只用 Node 自带模块：本机没有 pnpm（DSH 的 `dsh plugin add` 要它），所以不走插件安装，在配置档补丁里用绝对路径挂成全局一行；工具对象照 DSH 的 `defineTool` 生成的形状手写，参数类型自己校验

## 3. 测了什么

| 测试 | 结果 |
|---|---|
| 自检 `node test.mjs`（不启动 DSH，临时目录里搭项目根 + 假的 ctx 调四个工具，写出的 JSON 另外直接读回核对） | 13 项全过 |
| 自检会不会响：故意改坏两处 | 「在根下面」只比前缀（`E:\ws2` 被当成在 `E:\ws` 下面）→ 2 项没过；清点不跳过弃用文件夹 → 3 项没过 |
| 大厅里：「先列出项目，再把每一首都认领一下」 | 45 秒：`project_list` 一次 + `project_create` 并行 5 次（只传歌名）→ 侧栏多了 5 组；重启 DSH 后还在。沙箱外核对：5 个 `sv-project.json` 的修改时间都还是导入时的 13:10:07（认领确实没改内容） |
| 《天星问》下面：「这首歌现在做到哪了？还剩什么没做？」 | 32 秒、2 步：从上下文知道是哪首、什么状态，自己调 `project_status` 看备注 → 答对了（r01「可以」、77 BPM、464 字、八度改了 19 个；节拍器还没听、发布前要确认授权；项目文件夹还是空的、产物在外部素材里）。有一句「r02 以后未开始」是它自己推的 |
| 开销 | 新会话起手 4.8K → **5.4K token（29% → 33%）**：多的约 600 是四个工具的说明 + 那一小段 |

**测出来改掉的一处**：认领时每首都回了完整详情，一次认领 5 首上下文一下用到 49% → 认领只回一句（自检里加了一条：认领的回复必须短于 120 字）。
