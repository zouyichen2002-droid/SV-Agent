| 步 | 做什么 | 依据 |
|---|---|---|
| 逐字时间 | SV 工程里每个音的起止 → 对回歌词原文的字（中文按字的拼音、日语按词的读音、英文按词；M1-03 修歌词用的同一个对齐） | 工程默认用 rNN 里**最近改过的那份** `.svp`：你在 SV 里改了存盘、或另存了一份，用的都是你最后动的那份；吸格线前的备份不算 |
| 对齐 | 成品音频比工程晚几秒 → 字幕整体平移（见 §3） | 你在 FL 里混的成品，前面剪了、加了空白，字幕就会整体错位 |
| 成片 | 图铺满 1920×1080、整首缓慢推近 1.00 → 1.08；几张图平均分、交叉淡化 1 秒；底部渐暗；字幕逐字变色（ASS 卡拉 OK，行前 0.5 秒出来）；第一句前放标题、署名 | 编码先试显卡（h264_nvenc，要驱动 610 以上，这台是 591 → 不行），不行就 libx264（CRF 18）；AAC 320k |
| 剪映草稿 | 同一套时间；歌词一行一段，「卡拉OK」入场动画从出来到这一行唱完匀速变色 | 剪映的卡拉OK动画不能逐字设时间 → **逐字精确的变色在成片里**；剪映里是一行匀速的 |

规矩（插件管）：一版一个 `视频\vNN\`，号不复用；**做好的（有 `说明.md`）Agent 不能改**，要改就再做一版；没做完 / 被停的改名「弃用_vNN（…）」，不删；
**剪映的草稿文件夹 Agent 不能写**（只许 `video_run` 新建）；渲染只用 CPU、低优先级，不用让出本地大模型。

## 3. 对齐：成品音频和工程差几秒

伴奏是两边共有的（工程里放的是分离出来的伴奏，你的成品里也是它）→ 两边的「起音包络」（每 10 毫秒，频谱比上一帧涨了多少）做互相关，峰在哪 = 差几秒。
再一段一段查（30 秒一段、每 15 秒一段，每段 ±30 秒里找自己的峰）：前后差得不一样 = 中间剪过 / 加过段落。

**怎么判**：峰的相关 ≥ 0.30、且比 0.5 秒以外的最高峰高出 0.08 → 可信 → 平移（差不到 0.02 秒不动）；不可信 → 不平移、在结果和 `说明.md` 里提醒你。
阈值是 10-01 拿下面这些真歌定的（参考 = 《逃跑的天使》分离出来的伴奏，除非另说）：

| 拿来比的 | 结果 | 相关 / 次峰 | 判 |
|---|---|---|---|
| 原曲（和伴奏对齐的） | 差 0.00 秒，13 段全对得上 | 0.86 / 0.64 | 对 |
| 原曲前面加 2 秒空白 | 晚 2.00 秒 | 0.87 / 0.64 | 对 |
| 原曲剪掉前 5 秒 | 早 5.00 秒 | 0.86 / 0.65 | 对 |
| 原曲中间剪掉 10 秒（90–100 秒） | 整首不可信；分段：第 0 秒起对得上、第 90 秒起早 10.00 秒 | 0.43 / 0.38 | 对（提醒「中间剪过」，不平移） |
| 另外三首歌（怪物、祈愿、那些我恐惧至极的事） | 不可信 | 0.02–0.03 | 对（提醒「是不是给错了歌」） |
| 兰音翻唱的《调查中》对 原唱分离出的伴奏 | 早 2.93 秒；第 180 秒起又差 −23.44 秒 | 0.37 / 0.26 | 对（翻唱版比原唱短 27 秒，结尾剪过 —— 提醒那段会错位） |
| 《调查中（原唱）》对 自己的伴奏 | 差 0.00 秒 | 0.66 / 0.36 | 对 |

合成的自检（`python audio_offset.py --selftest`）：加 1.234 秒空白 → 1.237；剪 3.5 秒 → −3.498；对齐 → 0.002；给错歌 → 不可信。

**还不会的**：中间剪过段落时只提醒、不分段平移（真碰到再做）；变过速的成品对不上（会判不可信、提醒）。

### 5.1 成片里的（我们自己画字幕：每个字按它自己唱的时间动）

`worker/lyric_fx.py`；`lyric_video.py --fx <样式>`、`video_run.py --fx`、DSH 里 `video_run` 的 `fx` 参数都接好了。

| 样式 | 什么样 |
|---|---|
| 平铺（默认，原来的） | 整行一条，唱到哪亮到哪（卡拉 OK 从左往右填色） |
| 弹跳 | 唱到的字跳一下（0.10 秒起、0.16 秒落，抬高字高的 20%、放大到 115%）、变亮色 |
| 发光 | 唱到的字变亮，背后一圈橙色光晕先最亮、唱完 0.6 秒内暗成余光 |
| 浮现 | 整行的字一个个从下面飘上来、由糊变清；唱到的字慢慢变色；唱完一个个往上飘走 |
| 逐字出现 | 先只有很淡的影子；唱到哪个字，哪个字从 150%、糊的「弹」到原样 |
| 竖排古风 | 华文行楷竖排在右边；唱到哪个字，哪个字像墨一样晕开（先金色、唱完变白）；下一句出来时这一句往左挪、变淡，再退场；间奏长就原地淡出 |

**排版要自己算**（每个字单独一条字幕、定在它自己的位置）：字宽从字体文件读，libass 把字体的 winAscent + winDescent 当成字号那么高。
核对办法（`python lyric_fx.py --calibrate`）：同一行让 libass 自己排一遍，我们排的每个字单独画一张，看每个字要挪几个像素才和 libass 排的重合：

| 测的行（自己写的句子） | 结果 |
|---|---|
| 中文 15 字（微软雅黑粗） | 每个字差 0 像素 |
| 日文 8 个词（游ゴシック粗） | 差 0 |
| 英文 9 个词（Segoe UI 粗） | 差 +2 … −1（词之间的空格有一点误差；只出现我们排的那份，看不出来） |
| 中文 37 字，放不下要缩小 | 第一次两头差 8 像素（缩到 57.3 号 —— libass 对非整数字号的字宽和算的不一样）→ 改成缩到整数字号 → 差 0 |

### 5.2 剪映里的（剪映自带的文字动画）

剪映的「卡拉OK」是一种入场动画：换成别的入场动画，就没有唱到哪亮到哪了（一句只能有一个入场）。所以剪映里是二选一：卡拉OK，或者花样的入场 / 出场 / 循环。

| 组 | 剪映动画 |
|---|---|
| 1 | 卡拉OK（现在用的） |
| 2 | 逐字显影（入场时长 = 这一句唱的时间 → 唱到哪显到哪，匀速）＋ 渐隐 |
| 3 | 逐字弹跳（0.8 秒）＋ 渐隐 |
| 4 | 发光闪入 ＋ 循环「文字泛光」＋ 发光闪出 |
| 5 | 逐字旋入（0.8 秒）＋ 逐字虚影 |
| 6 | 剪映字体「古风小楷」＋ 水墨晕开（入、出） |

### 5.4 可爱（10-02：照你给的参考做）

你给了 B 站《樱草哀歌》/ 星尘infinity（UP 主心脏扭蛋_rabbitrite）的两张截图：「我想做类似这样的效果」「能有一定动效的可爱字体，带颜色」。
