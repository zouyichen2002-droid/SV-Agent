## 2. 做了什么

```
 项目文件夹 E:\sv-agent-workspace\<歌名>\
   ├─ r01\  r02\ …          ← 一版一个文件夹（照 M1 的规矩）；弃用的改名「弃用_rNN（原因）」，不删，编号不复用
 快照库 E:\sv-agent-data\snapshots\<歌名>\      ← 工作区外面：Agent 的沙箱写不进去
   ├─ artifacts.json          ← 清单：每一版的开 / 交付时间、交付时每个文件的指纹、你后来动了什么
   └─ 快照\rNN\<文件>_作者改_<时间>.<扩展名>
```

| 工具 | 做什么 |
|---|---|
| `artifact_new_version` | 开下一版 `rNN\`，给命名建议 `<歌名>_<内容>_rNN.svp` |
| `artifact_seal` | 交付：记下每个文件的指纹 = 交给你时的样子；之后这一版不能再改、不能往里加 |
| `artifact_discard` | 弃用：改名，不删 |
| `artifact_list` | 每一版的状态、你改了什么、快照在哪 |

- **自动备份**：插件盯着项目根（`fs.watch`）；已交付的版本里有动静 → 2 秒后比对指纹：文件变了（你改了存盘）、多了文件（你另存）→ 马上拷进快照库；
  挪走 / 删了 → 记下来；原样放回 → 记「放回来了」、不再拷。DSH 关着时你改的，下次启动时补查
- **拦住覆盖**：DSH 的工具拦截（`ctx.tools.guard`）—— Agent 用 `write` / `edit` 碰已交付版本里的任何文件，直接拒绝，理由里告诉它另开一版
- **拦不住的**：`pwsh` 跑的是任意命令 → 靠快照兜底（改动一出现就拷走）
- 每一步给模型一小段（最近 3 版的状态，例如「r01 已交付（创作者动过 1 处，快照已存）」）—— 放在运行时上下文里
- 「这个目录属于哪个项目」直接用 sv-project 里测过的函数，不重写一遍

## 3. 测了什么

| 测试 | 结果 |
|---|---|
| 自检 `node test.mjs`：照你真用的顺序走（开一版 → 写 → 交付 → 你改了存盘 / 另存 / 再改 → 挪走又放回 → 弃用），快照一律直接比对拷出来的内容，最后用真的 `fs.watch` 测「一存盘就备份」 | 15 项全过 |
| 自检会不会响：故意改坏三处 | 拦截永远放行 → 1 项没过；另存的新文件不拷 → 2 项没过；盯文件收到动静不查 → 1 项没过 |
| DSH 里：大厅说「新建一个翻唱项目，名字叫『阶段2测试』……」 | 31 秒，侧栏里出现 |
| 「阶段2测试」下面：「开新的一版，写一个占位工程和一句话说明，然后交付」 | 55 秒、4 步：开 r01 → 写两个文件（按命名建议起名）→ 交付；沙箱外核对清单里记了两个文件的指纹 |
| 我扮演你：在 DSH 外面改 r01 的工程文件（像在 SV 里改了存盘） | **约 2 秒后自动拷进快照库**（`…_作者改_20261001-133208.svp`），和改后的文件逐字节一样 |
| 「把 r01 那个工程文件里的 test 改成 2」 | Agent 从上下文知道 r01 已交付、你改过，**没去碰 r01**，先问「要不要开 r02」；我替你选了「开 r02」→ 2 分 37 秒：开 r02、读 r01、写 r02（**你在 SV 里加的那一处也原样带过去了**）、交付 r02；r01 一字没变 |
| 「这是在测试拦截：直接用 write 往 r01 写 {"test":3}」 | 轨迹里确实调了 `write`，**被拒**：「r01 已经在 2026-10-01 13:31 交付给创作者，创作者还改过，里面的文件不能覆盖、修改，也不能往里加……」；沙箱外核对 r01 还和你那次存盘的快照一样 |
| 开销 | 新会话起手 5.4K → **5.8K token（33% → 36%）** |
