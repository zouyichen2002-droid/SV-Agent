## 2. 做了什么

```
 你：「翻唱这首」+ 链接 / 本地音频 / 已有  +  一条「歌词：…」（或歌词已经在 素材\歌词_原文.txt）
   │
 sv-cover 插件（DSH 进程里）
   ① 取歌词（原样）→ 素材\歌词_原文.txt      ② 开下一版 rNN（sv-artifact 的规矩）     ③ 起后台任务，马上返回
   ④ 等 Agent 这一轮说完 → 卸掉本地大模型
   ⑤ 起 Worker（不进沙箱，见 §5.1）── 进度：日志\进度.jsonl → 任务列表 / 模型
   ⑥ 成功：交付 rNN、记项目状态；失败：rNN 留着「进行中」     ⑦ 载回大模型 → DSH 唤醒 Agent → present 交付工程
   │
 worker/cover_run.py（M1 的 9 步串成一条命令；做完的步跳过）
   原曲 → 歌词（认语言 + 清理）→ 分离（显卡）→ 补段 ─┬→ 扒谱（GAME + 听写）→ 多声部（basic-pitch）─┐
                                                       └→ 找拍子（单线程约 12 分钟，并行）──────────┴→ 模板（星尘）→ rNN 工程
```

- 产物全在项目文件夹里：`素材\` `分离\` `拍子\` `扒谱\` `模板\` `rNN\` `日志\`
- 编排写成 Python（「Python 只管算」），插件只管状态和决定（开版本、交付、让出 / 载回大模型、进度）

## 3. 测了什么

### 3.1 分离换显卡

《逃跑的天使》显卡版对 CPU 版：波形差约 1%（信噪比 36–42 dB；关掉 TF32 一模一样 → 不是 TF32 来的，是 32 位浮点累加顺序）；
拿去扒谱，音符 F1 0.994 —— 比 Vocal2Midi 同一份主唱跑两次的差别（0.991）还小 → 你定用显卡。分离 25 分钟 → 约 75 秒。

### 3.2 Worker 对 M1

《逃跑的天使》用 Worker 一条命令重跑，对 M1 的 r02：速度一样，音符 F1 0.986（Vocal2Midi 自己跑两次也有 0.99 上下的波动），放上歌词的音 581。

### 3.3 DSH 里端到端（《逃跑的天使》）

| 测的 | 结果 |

## 5. 还没做的 / 要你知道的

### 5.1 Worker 不进沙箱（我定的，要你知道）

- DSH 的 Windows 沙箱（受限令牌 + 低完整性）里：
  1. numba（librosa 用）一 import 就往 site-packages 写缓存，写不了就一直重试 → 卡死。修：缓存挪到临时目录（要在 Worker 自己的进程里设，不只是传给子程序）
  2. Vocal2Midi 的听写（Qwen3-ASR）写死了另起进程（multiprocessing），Windows 上走命名管道，沙箱不许开 → WinError 5。这个绕不过去（要改它的代码）
- 所以 `sandbox: false`：Worker 是我们自己的固定流程，模型只能给「来源」和「用不用歌词」两样，插件先校验（链接只许 http(s)、本地文件要存在、或「已有」）；Worker 只往这首歌的项目文件夹里写
- 要恢复沙箱：等 Vocal2Midi 的听写能不另起进程，或者给沙箱开命名管道
