## 1. 一句话 · 铁律 · 方向

**一句话**：在你自己的电脑上，把「一首别人的歌（或 Suno 生成的歌）」变成「星尘唱的、能直接在 SynthV 里改的工程」，再一路做到视频和 B 站投稿；以后再长成个人创作工作台。

**铁律**（PRD §0，你 09-24 定，压倒其余全部）：**这个项目只是为了让你能更好、更快地产出虚拟歌手歌曲作品。** 每样东西都要答得上「让出歌更好吗 / 更快吗」，答不上就砍。架构感不是验收项。

**方向**（PRD §0.4，v3.0，10-01 你定）：基于 DeepSeek Harness（DSH）的**个人创作工作台**。
- DSH 原样当 Agent 底座（会话、工具、审批、沙箱、网页界面、模型调用）
- 我们只写创作领域的插件（TypeScript）+ Python Worker（算东西、出候选文件）
- 第一个真实 Skill 是翻唱（Cover Skill）
- 全部本地模型；上下文不够时用 DeepSeek 接口（密钥你开、你填）
- 分工：DSH / TS 管状态和决定，Python 只管算

**现阶段实际怎么用**：DSH 的阶段 0–4、6、10 做过、测过；**10-04 以后的翻唱，大部分是我（Claude Code）在这个对话里直接跑 Python 流程**，没走 DSH 对话（更快、能边跑边修）。DSH 里的 sv-cover / sv-video 插件仍然能用，但这几天新加的规矩、和声、原 PV 做法都没接进 DSH 的 Skill 说明里（见 §23）。

## 3. 现在能做什么、不能做什么

**能做（实测过）**
- B 站链接 / 本地音频 → 分离 → 找拍子 → 扒谱 → 按你给的歌词放字 → 挑八度 → 一组规矩 → 吸格线 → 星尘唱的 `.svp`（伴奏、原曲主唱参考轨都在里面）。一首 4 分钟的歌约 15–26 分钟（找拍子占大头），重跑后面几步十几秒
- 中文主流歌、日语效果好；英文（IA 唱英文那首）不行；戏腔没做
- 副歌八度和声（上 / 下八度两条轨，按句或按秒指定段落）
- 你改完以后：逐音对比、找规律、试规矩、在你改过的几首上验证、你点头再进流程
- 歌词视频（你的图 + 逐字字幕 + 特效样式 + 剪映草稿）；代码画的 MV（《逃跑的天使》）；**原 PV 翻唱视频**（下载 1080p、去 B 站水印、剪片尾广告、换混音）
- 封面（原封面 + 星尘立绘）；B 站投稿页填标题 / 标签 / 简介 / 声明（上传文件和点投稿是你）

**不能 / 不好**
- **多层叠唱的念唱**（《刽子手》：至少 3 层和声、不同八度）—— 现在只会单轨、一个音，你 10-13 说「还是不行」、先不做
- 主唱自己叠了一个八度的地方拆不开
- 和声只会「主旋律原样上 / 下一个八度」，不会编和声
- 英文
- 原创（作曲、作词）—— 推迟到翻唱完全实现之后（PRD v2.6）
- 自动试听不做（你说直接开 SV 听）
- 不碰 Suno 的生成（Suno 能认出 AI 操作，你自己点）

## 4. 一首歌从链接到 B 站：完整流程

```
你给链接（+ 注意事项）
  │
  ├─ 我：读视频信息（标题、UP、时长、staff、原唱）—— 内置浏览器读 B 站接口，视频暂停静音
  ├─ 我：找歌词（萌娘百科），存草稿；有括号应答 / 旁白 / 英文 / 特殊写法的问你怎么处理
  ├─ 我：问你下载（文件、来源、大小）→ 你「可以」
  ├─ 建项目 <工作区>\<歌名>\（sv-project.json）
  ├─ 下原曲音频（两个镜像各一份、逐字节比）
  ├─ cover_run.py r01（后台、低优先级）
  ├─ 我：读报告，列要你听的地方 → 你在 SV 里改、存盘
  ├─ 我：存你改的快照、逐音对比你改了什么、试规矩（多首验证）→ 你「都加上」→ 进流程、回归
  ├─ 和声（你说副歌段 / 哪几句）→ 整体 −4 dB 防削顶
  ├─ 你导出混音（双声道、不旁通增益）→ 我查削顶、和原曲对齐
  ├─ PV：原 PV（你说 V 圈默许）→ 登录拿 1080p → 去水印 → 查片尾 → 换混音；封面：原封面 + 星尘立绘
  ├─ B 站投稿页：你上传视频和封面 → 我填标题 / 标签 / 简介 / 声明 → 你点「立即投稿」
  └─ 我：稿件管理里查 BV 号，记进项目
```

## 5. 翻唱流水线（`worker/cover_run.py`）逐步说明

一条命令：`<python> worker/cover_run.py <项目文件夹> --round rNN --source <链接 | 本地音频 | 已有> [--lyrics 歌词.txt] [--language auto|zh|en|ja] [--octave-pick on|off]`

- 进程自己设成**低于正常优先级**（你说在你机器上跑重活要低优先级，卡就立刻停）
- 每一步做过就跳过（文件在就不重做）；重出一版只跑最后一步，十几秒
- 每步写日志 `日志\翻唱_rNN.json`；最后写 `rNN\说明.md`
- 配置：`worker/cover_config.json`（各环境的 python、ffmpeg、yt-dlp、模板、默认声库星尘、线程数）

| 步 | 做什么 | 用什么 | 产物 |
|---|---|---|---|
| 原曲 | 链接 → yt-dlp 下（B 站老视频 yt-dlp 常下不了 → 我用内置浏览器拿播放地址分段下）；本地音频直接转 | ffmpeg → 44.1 kHz 立体声 16 位 | `素材\原曲整首.wav`、`source.json` |
| 歌词 | 你给的原文 → 清洗成「要唱的字」；按歌词认语言 | `clean_lyrics.py` | `素材\歌词_原文.txt`、`歌词_要唱的字.txt` |
| 分离 | 人声 / 伴奏（Mel-Roformer），再把人声拆主唱 / 叠唱（karaoke 模型）；核对长度、零点、加起来 ≈ 原曲、主唱比叠唱响 | audio-separator（separator 环境，显卡约 75–110 秒） | `分离\` 四条 |
| 找拍子 | 粗估 BPM → 分段、找「1」、小节线、速度表；和后面几步一起跑（最近三首实测 13.4–24.3 分钟） | `beat_grid` / `tempo_map`（m5-00） | `拍子\tempo_map.json` |
| 补段 | 主唱分轨整段没声、整条人声又和平时主唱一样响 → 用整条人声补（分离把主唱分进叠唱的地方） | `hybrid_lead.py` | `分离\主唱_缺的段用整条人声补.wav(.json)` |
| 扒谱 | GAME 切音 + Qwen3-ASR 听写 | Vocal2Midi（vocal2midi 环境，DirectML 显卡约 40–60 秒） | `扒谱\<歌名>_v2m_asr_主唱补段.mid` |
| 强制对齐 | Vocal2Midi「给原歌词」模式（HubertFA）—— 只拿每个字的时间，它重切的音不用（09-29 你说音准优先） | 同上 | `扒谱\<歌名>_v2m_给原歌词_主唱补段.mid` |
| 多声部 | basic-pitch，挑八度的第二个裁判 | pi-audio 环境 | `扒谱\basic_pitch_raw_主唱补段.json` |
| 模板 | 星尘模板 + 这首的速度表（速度表变了就把旧模板挪开重做） | `make_template.py` | `模板\模板_<歌名>.svp` |
| 生成工程 | 见 §6 | `song_round.py` | `rNN\<歌名>_扒谱_rNN.svp`、`_吸格线前.svp`、`.json` 报告、`说明.md` |

工程里的轨：**伴奏**（分离出的伴奏）、**原曲主唱**（分离 + 补段，参考，静音）、**扒谱 rNN（第一版 · 吸格线）**（星尘唱）。默认音量伴奏 +1.7、主唱 +3.5；导出：代码设双声道（numChannels=2），不旁通增益是星尘模板本来的值（代码没碰）。

## 6. 生成工程（`spikes/m1-01-voice-to-midi/song_round.py`）里的每一条规矩

顺序就是代码里的顺序。每条都带自检（造一段数据、注入缺陷、确认会报），自检不过整版不出。

| # | 规矩 | 谁定的 / 什么时候 | 做法 | 依据（实测） |
|---|---|---|---|---|

| 2 | **按歌词修歌词**（换字、补空位、拆音、多的音写拖音、补音） | 你，09-29（C03b） | `repair_lyrics.py`；只改字、不动音（音准优先） | 《傍晚》r04 185 字全对、音一个不变 |
| 3 | **歌词落位 v2** | 你，10-06《公主》「歌词落位有很大问题」 | 强制对齐给时间锚点 + 听写拼音一起做 DP（`lyric_fuse.py`） | 《刽子手》对你手改的 240→247 |
| 3b | **按行落位**（没提交） | 10-13《刽子手》r03 两处错 | 离本行其他锚点太远的锚点不算；前后锚点跨行又隔 3 秒以上，不跨这个空插值、在本行里往外推 | 五首你改过的只有《刽子手》3 处变（都变对）；12 首回归别的一个不变 |
| 4 | **「着」默认读 zhe** | 你，10-08 | 固定词（着落 / 着手 / 着想 / 着陆 zhuo，着急 / 着火 / 着凉 / 着迷 / 睡着 zhao）照原读音 | 《那些我恐惧至极的事》1:48 |

## 7. 歌词：来源、清洗、落位

## 9. 和声

- 工具：`worker/add_octave_harmony.py`
- 做法：主旋律在指定段落的音复制两份，**上八度、下八度各一条轨**，比主唱低 6 dB、声库和主唱一样；起止、歌词、属性原样，只改音高；默认开下八度、上八度静音（你常切成上八度）
- 段落：`--lines 9-12,21-24`（按句，用做字幕那套代码对出每句唱的起止）或 `--section 79.0-102.9`（按秒）
  - **按句取边界会出错**：《由》r03 漏了第一个音（四舍五入）、《那些》第二段漏最后一个字（差 1 毫秒）、《弈》第二段一直延伸到英文段 → 现在我都先干跑一次、看两头复制了哪个音，有问题改按秒
- **加和声后每条轨 −4 dB**（§10）—— 是我每次手动做的，和声工具里没有这一步
- 和声改完要验：第二个裁判逐音比（和声 = 主唱那几段 ±12，别的轨除音量外原样）
- 你改主唱后和声要跟着改：手动或 `sync_harmony`（草稿脚本）
- 吟唱等非副歌也能加（《弈》r03 把吟唱 14 个音加进现有两条和声轨）
- **不会编和声**（不是八度的那种）；**念唱多层叠唱**也没做

## 22. 检验方法：回归、对照、第二个裁判

- **和你改的版本对照**（最主要的尺子）：重新生成原版（同样的输入、同样的代码）→ 逐音比你改了什么（长、起点、音高、字、删、加）；打分「同时间同字」「再加同音高」（±30 ms）
- **候选规矩的验法**：先在当前这首上看能不能复现你的改法，再到你改过的其他歌（《公主》《那些》《影子小姐》《弈》《刽子手》09-30）上看会不会改坏；**过了才拿给你定**，你说加才加
- **回归**：12 首（INTERGALACTIA、倒瞰清白、刽子手、夜舞、怪物、由、祈愿、调查中（原唱）、逃跑的天使、那些我恐惧至极的事、影子小姐、弈）重新生成到草稿目录，比加规矩前后哪些音变了；《傍晚》基线 regress_r05
- **第二个裁判**：检查器自己会错（M0 里错了三次），所以每个检查都配一个独立的复核（例：和声生成后另写脚本逐音比；水印用每像素最暗值复核；混音用和上一份的差值看哪里变了）
- **自检 + 注入缺陷**：每条规矩的自检要能被故意改坏的代码打红（10-13 的「空隙」那条第一次没打红，补了用例）
- **Vocal2Midi 每次跑不一样**（F1 0.987–0.991）→ 回归只比后面几步，扒谱结果固定用文件里的
