# sv-artifact · Artifact 插件（v3 阶段 2）

管每首歌的**版本**，保证**不覆盖创作者改过的文件**。创作者 10-01 定：「自动备份 + 拦住覆盖」；试听先不做（放到阶段 5「MIDI → 钢琴试听」）。

```
 项目文件夹 E:\sv-agent-workspace\<歌名>\        （sv-project 插件管）
   ├─ r01\  ← 一版一个文件夹（和 M1 一样）：工程、MIDI、说明……
   ├─ r02\
   └─ 弃用_r03（原因）\  ← 弃用的改名，不删；编号不复用

 快照库 E:\sv-agent-data\snapshots\<歌名>\        （工作区外面：Agent 的沙箱写不进去）
   ├─ artifacts.json          ← 清单：每一版什么时候开、什么时候交付、交付时每个文件的指纹（sha256）、创作者后来动了什么
   └─ 快照\r01\<文件>_作者改_<时间>.svp   ← 创作者改过的样子，一改就拷
```

| 工具 | 做什么 |
|---|---|
| `artifact_new_version` | 开新的一版：建下一个 `rNN\`，返回路径和命名建议（`<歌名>_<内容>_rNN.svp`） |
| `artifact_seal` | 交付一版：记下每个文件的指纹 = 交给创作者时的样子。交付以后这一版不能再改、不能往里加 |
| `artifact_discard` | 弃用一版：改名成「弃用_rNN（原因）」，文件都在 |
| `artifact_list` | 每一版的状态、交付时的文件、创作者后来改了什么、快照在哪 |

**保护怎么做的**

- **自动备份**：插件用 `fs.watch` 盯着整个项目根；已交付的版本里有动静 → 2 秒后（SV 存盘会连写几次）比对指纹：
  文件变了（创作者在 SV 里改了存盘）→「改了」；多了文件（创作者另存）→「新加了」；没了 →「挪走 / 删了」（只记、拷不了）；原样放回 →「又放回来了」（不再拷）。
  变了和多了的**马上拷进快照库**（超过 50 MB 的只记不拷；版本里通常只有工程、MIDI、说明）。DSH 关着时的改动，下次启动时补查。
- **拦住覆盖**：`ctx.tools.guard` —— Agent 用 `write` / `edit` 碰已交付版本里的任何文件，直接拒绝，理由里告诉它另开一版。
- **拦不住的**：`pwsh` 跑的是任意命令，没法可靠地判断它写哪个文件 → 靠快照兜底（改动一出现就拷走）。
- 清单和快照都在工作区外面：Agent 在沙箱里改不了它们；插件本身在 DSH 进程里、以创作者的权限运行，只往快照库写。

每一步给模型一小段（运行时上下文，追加、不碰系统提示词）：最近 3 版的状态，例如「版本：r02 进行中；r01 已交付（创作者动过 2 处，快照已存）。已交付的版本不能改、不能往里写，要改就另开一版。」

## 怎么挂的

和 sv-project 一样：只用 Node 自带模块 + 同仓库的 `../sv-project/index.js`（判断「这个目录属于哪个项目」），在配置档补丁里用绝对路径挂成全局一行：

```yaml
    - id: sv-artifact
      name: E:/sv-bridge/dsh/plugins/sv-artifact/index.js
      config:
        root: E:/sv-agent-workspace
        store: E:/sv-agent-data/snapshots
```

快照库放在项目根下面会直接报错（沙箱能写那里）。

## 自检

```
node test.mjs
```

照创作者真用的顺序走：Agent 开一版 → 写 → 交付 → 创作者改了存盘 / 另存 / 再改 → 挪走又放回 → 弃用；快照一律直接比对拷出来的文件内容；最后用真的 `fs.watch` 测「一存盘就备份」。
10-01 故意改坏三处验证测试会响：拦截永远放行 → 1 项没过；另存的新文件不拷快照 → 2 项没过；盯文件收到动静不查 → 1 项没过。
