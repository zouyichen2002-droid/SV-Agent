# 翻唱一首歌（Cover Skill）

1. **先确认在这首歌的项目里**：上下文里有「SV 项目：《…》」。
   在大厅里：先用 project_create 建项目（翻唱，名字用歌名），再请创作者到侧栏那首歌下面开新会话、把要求再说一次。
2. **要两样东西**：
   - 来源：链接（B 站等）、本地音频的绝对路径，或「已有」（项目里已经有 `素材\原曲整首.wav`）
   - 歌词：创作者发一条以「歌词：」开头的消息 —— 插件会从消息里原样取，**你不要重抄、不要改写歌词**。
     没看到就问一句；创作者说这首不用歌词 → `use_lyrics: false`
   - 英文、日语的歌一样：语言按歌词自动认（有假名 → 日语，只有字母 → 英文），星尘用 SV 的跨语种唱，不用另外说
   缺哪样就用 ask_user_question 问清楚再调。
   - 挑八度默认开着；**只有创作者说这首「不挑八度」时**才加 `octave_pick: false`（不要自己决定关）
   - 记忆里这首（或所有歌）生效的偏好，插件会自动用、在说明里写明 —— 你不用另传；创作者这次说的和偏好不一样，就照他这次说的传
3. **调 cover_run**（source、use_lyrics、octave_pick、note）。它马上返回，在后台跑约 15–25 分钟；这段时间本地大模型会让出来。
   调完用一两句话告诉创作者：已经开始、大概多久、跑完会自动告诉创作者结果 —— **然后结束这一轮**。不要调 job_output 等它，不要再做别的事。
4. **跑完你会被唤醒**，任务结果里有工程路径、扒了多少音、改了多少八度：
   - 成功：用 present 交付那个 `.svp`（和同一版里的 `说明.md`），两三句话说结果，请创作者在 SV 里听、直接改 —— 不要编没看到的数字
   - 失败：照任务结果说是哪一步错了、日志在哪，问创作者要不要接着跑；同一首再跑一次会接着做（做完的步跳过）。
     **不要自己去读脚本、查代码找原因**（10-01 有一次读了 6 分多钟、上下文用到 92%）—— 修代码是开发那边的事
5. **别做**：别用 pwsh 自己跑翻唱脚本；别改已经交付的版本（要改就再跑一次，会另开一版）；别把歌词贴回对话里。
