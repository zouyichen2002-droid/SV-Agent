# ADR-0001 — 音节边界用 CTC 强制对齐，放弃 DP 分段与网格量化

| | |
|---|---|
| 状态 | **已接受**，但只覆盖"边界定位"这一步（见文末"没有解决的问题"） |
| 日期 | 决策发生 2026-08-20 ／ 补记 2026-08-20 |
| 决策者 | 上一会话提出并实施；用户以实听验收（v4 被判"效果一般"，但否决的不是本条） |
| 影响范围 | 线 1 翻唱管线 阶段 2–3（逐行 / 逐字对齐） |

## 背景

从参考干声 + LRC 反推 SynthV 音符，要定三样东西：每个字的**起音**、**时长**、**音高**。
本条只管第一件 —— 字级边界从哪来。

素材：《潮声回响》，实测 86.00 BPM，干声 stem 来自 Demucs `--two-stems=vocals`，
LRC 33 个主唱行 / 315 字，覆盖 23.54–198.66s。

约束：`torchaudio` 不可安装（pypi 最高 2.11.0，会把 torch 2.13.0 降级弄坏），
所以任何依赖 `torchaudio.functional.forced_align` 的方案都要自己实现 Viterbi。

## 选项

**A · DP 分段（先实施的）**
用 LRC 每行字数作硬约束，在该行时间窗内对 f0 / 能量序列做动态规划切分，
代价函数偏好在能量谷和 f0 不连续处下刀。不需要额外模型，纯信号处理，几秒出结果。

**B · CTC 强制对齐**
用中文 wav2vec2 CTC 声学模型逐行做强制对齐
（`jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn`，1.28GB，词表 3503 / 3439 个单汉字，
对本曲用字覆盖 170/179 = 95.0%），Viterbi 自实现。
代价：1.28GB 模型（实际下了六次才通过 sha256 校验），且引入一个不受本项目控制的第三方声学先验。

**C · 网格量化兜底**
不做声学分段，把音节按拍网格（16 分音符）均摊或吸附。

## 决策

**选 B。** A 被量化结果否掉，C 被实测反例否掉。

## 理由（证据）

| 方案 | 音高偏差（对**独立**实测 f0） | 字级结果 |
|---|---|---|
| A · DP 分段 | **+2.6 半音** | 轨 6，286 音符，整体只有 50–64% |
| B · CTC 对齐 | **+0.22 半音**（在曲线 A 有数据的音符上） | 33/33 行、300/315 字直接对齐（95.2%），全曲 11 秒（CPU 16 线程） |

- C 有直接反例：16 分音符 snap **64.9%** vs 不 snap **66.7%** —— 量化让结果**变差**。
  演唱是表情性的，硬对网格没有收益。
- B 的运行代价可控：11 秒跑完全曲，1.28GB 是一次性成本。

**A 为什么会差一个数量级**：DP 的代价函数看的是能量谷和 f0 不连续，
但汉语演唱里连续元音之间既没有能量谷也没有 f0 断点（"潮声回响"四个字可以一口气连唱），
下刀点缺少物理依据 —— 它在优化一个和真实音节边界只有弱相关的目标。
CTC 看的是音素后验，直接回答"这一帧像不像这个字的声学证据"。

## CTC 的已知性质（后续实现必须遵守，这三条各自都有踩坑记录）

1. **尖峰式**：每字只在一帧爆发（跨度 ~20ms）。**尖峰给的是起音，不是时长。**
   时长取"到下一字起音"，上限 1.70s。
2. **两字尖峰相距 <85ms 一定是对齐误差。** 处理方式是**按行摊开起音、保最小间距 85ms**。
   上一会话用"合并"处理，**丢了 43 个字**。
3. 消重叠**不要**写成 `duration = max(下限, 间隙)` —— 间隙小于下限时反而造出重叠。
   v3 因此产生 64 对重叠、中位 70ms。

## 这条决策没有解决的问题

**CTC 对齐成功 ≠ 管线成功。** 用户对 v4（轨 7，300 音符）的实听评价是"效果一般、很多歌词错位"。
根因不在边界，在另外两处，各自需要独立 ADR：

- **主唱和和声混在同一条 stem 里** —— LRC 有 9 个括号和声行与主唱行时间重叠，
  Demucs `--two-stems=vocals` 不区分主唱 / 和声。这是总闸门，下游所有问题都能追到它。
- **可信音高源只覆盖 43%** —— 曲线 A（1860 点）有 15 处 >1s 空洞（最大 32s）；
  退化到曲线 B 时偏差 +6.90、粗错 57.3%。最终 300 个音符里 **63 个（21%）没有任何声学证据**，
  是从邻居抄的。用户听到的"歌词错位"主要就是它们。

换句话说：本条 ADR 交付的是一个**正确但不充分**的组件。它可以直接复用，
但复用前必须先解决 stem 分离和音高证据覆盖率。

## 什么证据会推翻这条决策

1. **拿到干净的独立主唱 stem 后重跑 A/B 对照，A 的音高偏差进入 ±0.5 半音** ——
   说明 A 之前差是因为 stem 脏，不是方法错。那时 A 的"零模型依赖"就重新有价值。
2. **CTC 在某些行出现系统性整体偏移**（例如全行晚 100ms+）且逐行独立估偏移无法修正 ——
   说明 CTC 之上还需要一层，本条要被取代而非修补。
3. 换模型**不构成推翻**，只是换实现。候选：`kehanlu/mandarin-wav2vec2-aishell1`，
   390.6MB，词表覆盖 **99.4%**（现用 95.0%）。但架构是非标准的 `Wav2Vec2ForEspnetCTC`，
   **切换前必须先确认 CTC 头的权重键名能映射** —— 映射不上会让 `lm_head` 被随机初始化，
   然后静默输出垃圾对齐（这种失败不报错，只是结果变差，是最危险的一类）。
