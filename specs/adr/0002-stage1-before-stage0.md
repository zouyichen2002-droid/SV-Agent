# ADR-0002 — 起手点选阶段 1（音高证据层），不是阶段 0（stem 分离）

| | |
|---|---|
| 状态 | **已被取代 → [ADR-0005](0005-polyphonic-vocal-transcription.md)** |
| 日期 | 2026-08-20 |
| 决策者 | 用户拍板（选项 + 取舍由实现方给出） |
| 影响范围 | 线 1 翻唱管线的执行顺序；推翻交接文件 §5.2 与 §10 的因果排序 |

> **2026-08-22 取代说明**：本条的测量（分离最多解决 26% 的音高证据缺口）
> 在它自己的问题设定下成立，但**问题设定错了** —— 当时假设线 1 只要一条主唱。
> 用户澄清真实目标是「一条多声部人声轨 → 1 条主旋律 + N 条和声轨」之后，
> 分离不再是可选预处理，而是交付物本身。见 ADR-0005。
> 本条不删：它记录的「因果排序要靠实测而不是靠交接文件的断言」这个方法仍然成立。

## 背景

交接文件把「主唱和和声混在一条 stem 里」列为**总闸门**（§5.2：「下游所有问题都能追到这条」），
并据此建议从**阶段 0（用 karaoke 模型分离出独立主唱）**起手（§10）。

接手会话在动手前先复核了这个前提，结论是它站不住。

## 选项

**A · 按原计划先跑阶段 0 分离门槛**
装 `audio-separator`，下 karaoke 模型，跑分离，人工试听确认和声消失。
优点：能彻底排除一个变量，顺带验证「和声在上方八度」那个假设。

**B · 先做阶段 1（跨估计器音高证据层）**
装 RMVPE + torchcrepe，对全曲逐帧建立「哪些时刻有被独立确认的音高、哪些没有」的划分。

**C · 放弃自动转写，收敛到「人摆音符 + agent 调声」**
桥的写入路径已验证零失败（174/174、300/300）。最快能交出一个小而完整的东西，
但放弃了信号处理这块差异化。

**D · 先搭架构地基**（编排 / 门槛机制 / 配置化 / eval harness / 自写 MCP server）

## 决策

**选 B。**

## 理由（证据）

复核推翻了「分离是总闸门」这个前提。三条证据，都在 `specs/benchmark-facts-chaosheng.md`：

1. **和声在时间上是局部的。** 9 个括号行**全部**落在 92.85–151.88s，
   跨度 59.03s = 歌词跨度的 29.7%。区间外仍有 35 个主唱行 / 295 字 = **79.5% 的主唱字**。
2. **音高不可信时段 74% 落在和声区间之外。** 交接文件列的不可信段（80–103s、~127s、150–173s，
   合计约 46s）与和声区间求交只有约 12s。**分离做到完美，最多解决 26% 的音高证据缺口。**
3. **「重叠」的程度完全取决于假设的演唱速率。** 在物理下界（8 音节/秒）只有 1/9 的和声行
   必然重叠，且只重叠 0.53s。

反过来，音高证据覆盖率只有 43% 是**有直接因果链连到用户实听不通过的**：
覆盖不足 → 63 个音符（21%）没有声学证据、从邻居抄 → 用户听到「歌词错位」。

## 执行后的实测结果（这条决策已被验证）

阶段 1 做完后（三个估计器：torchcrepe / praat-ac / rmvpe，门限 0.2，≥2 一致）：

| 指标 | 决策前（交接文件） | 阶段 1 之后 |
|---|---|---|
| 音高证据覆盖（全曲） | 43% | **71.0%** |
| 演唱行覆盖中位 | — | **77.2%** |
| 覆盖 <50% 的主唱行 | — | **1 / 33** |
| **和声区间内 vs 区间外覆盖** | 假设区间内会明显更差 | **区间内 74.7% vs 区间外 65.4%** |

最后一行是对交接文件 §5.2 的直接反驳：**和声区间内的覆盖反而更高。**
分离质量不是这条管线的瓶颈。

另外，交接文件记录的三个 pyin 失效点里，最关键的那个（139.9–140.6s 锁三次次谐波，
正确 68.90 被报成 50.00）现在被解决了：证据层给 MIDI 69.00，偏差 +0.10 半音。

## 这条决策没有解决的问题

- **阶段 0 仍然要做，只是不在关键路径上。** 它现在的定位是「进一步提升覆盖率的手段」，
  以及验证「和声在主唱上方八度」那个假设（`specs/benchmark-facts-chaosheng.md` §4.2）。
- 覆盖率从 43% 提到 71% 之后，剩下的 29% 是不是真的没有声学证据、还是估计器集合不够，
  尚未定论。
- 「用哪几个估计器、门限定多少」是另一条独立决策，见 ADR-0004。

## 什么证据会推翻这条决策

- 阶段 0 做完后覆盖率从 71% 跳到 90%+ —— 说明分离终究是主因，只是被 43% 这个
  更早的瓶颈掩盖了。
- 覆盖率提到 71% 之后重建音符、用户实听仍然「很多歌词错位」，且错位位置与
  音高证据无关（例如全在起音上）—— 说明主因在时间对齐而不是音高，本条选错了战场。
