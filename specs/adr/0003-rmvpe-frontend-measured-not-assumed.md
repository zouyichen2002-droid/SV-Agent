| 影响范围 | `toolkit/svagent/pitch/rmvpe_arch.py`、`rmvpe_est.py`、`scripts/*rmvpe*.py` |

## 背景

RMVPE 的权重 `rmvpe.pt`（181,184,272 字节，sha256
`6d62215f4306e3ca278246188607209f09af3dc77ed4232efdd069798c4ec193`）
是一个**纯 `state_dict`**：741 个键、90.42M 参数，只有张量，没有网络定义、
没有 mel 前端参数、没有输出轴的物理含义。

要用它，必须自己补三样东西。**每一样写错都不会抛异常，只会静默输出偏掉的 f0** ——
正是 ADR-0001 文末点名的最危险失败类型（那里说的是 `lm_head` 被随机初始化）。

## 选项

**A · 按公开实现的常见约定写**
架构照 RVC 的 `rmvpe.py`，mel 用 `librosa.filters.mel` 默认值（Slaney 刻度）、幅度谱、
`fmin=30 / fmax=8000`，bin→cents 用 `20·bin + 1997.3796`。快，零实验成本。

**B · 只用 `load_state_dict(strict=True)` 把关**
形状对上就认为实现正确。

**C · 每一个「权重形状分辨不出来」的量都实测确定**
先用 strict 加载排除形状错，再对剩下的自由度设计能判真伪的实验。

## 决策

**选 C。** A 被实测否掉，B 被证明不充分。

## 理由（证据）

### A 错在哪：Slaney 刻度让音高系统性偏低 570 音分

按约定写完，合成正弦实测：

| 真值 | 测得 | 误差 |
|---|---|---|
| 98.00 Hz | 69.56 Hz | −593 音分 |
| 220.00 Hz | 158.28 Hz | −570 音分 |
| 440.00 Hz | 328.80 Hz | −504 音分 |

**模型照样输出干净的单峰显著图**（8 个非零 bin、形状正常、随频率单调），
只是数值全错。没有任何异常、没有任何警告。

真因是 **mel 用的是 HTK 刻度，不是 Slaney**。改成 `htk=True` 后，
经验标定出的截距是 **1998.33**，与约定值 1997.3796 只差 **+1.0 音分** ——
也就是说约定的**常数本来是对的，错的是喂给模型的 mel**。
这是最阴的一类错：常数抄对了，反而让人相信整条链是对的。

顺带定下：**功率谱优于幅度谱**（正弦误差中位 1.9 vs 3.0 音分，八度错 4.6% vs 6.8%）。

### B 错在哪：strict 加载抓不到三件事

`load_state_dict(strict=True)` 确实抓到了一个真错误（我第一版把 decoder 通道
写成从 256 起，权重要求从 512 起，intermediate 是 256→512 而不是 128→256）。
**但它对下面三件事完全无能，因为它们不改变任何张量的形状：**

| 自由度 | 两个选择 |
|---|---|
| `concat_order` | decoder 里 上采样结果 与 skip 连接 谁在前（通道数相同） |
| `flatten_mode` | (B,3,T,128) 摊成 GRU 的 384 维时，通道在外还是频率在外 |
| `input_layout` | mel 送进 unet 时时间轴放行还是放列（128 与 T 都能被 32 整除，都不报错） |

八种组合全部能 strict 加载、全部能跑完、全部输出 (B,T,360)。

### C 怎么做的：三条互不依赖的证据链

**证据 1 · 前向结构 —— 重采样自洽性**（`scripts/identify_rmvpe_forward.py`）

把同一段真实歌声按倍率 r 重采样，音高必然位移 `1200·log2(r)` 音分。
若输出轴是等间距 cents bin，则 `Δbin(r) = 1200·log2(r) / 每bin音分`，
**对不同的 r 必须解出同一个斜率**。这个判据不借任何其它估计器。

| 配置 | 斜率均值 | 斜率标准差 | 峰值置信 |
|---|---|---|---|
| **up_first / channel_major / time_rows** | **19.733** | **1.190** | **0.458** |
| skip_first / freq_major / time_rows | −6.031 | 78.585 | 0.190 |
| skip_first / freq_major / time_cols | −1.237 | 18.277 | 0.183 |
| 其余五种 | 高置信帧不足（峰值 0.001–0.010） | | |

唯一解。修正 mel 前端后同一判据给出 **20.202 ± 0.130**，六个倍率（±1 个八度范围内）全自洽。

**证据 2 · 截距 —— 稳健估计，不是最小二乘**

斜率固定后只剩一个标量。用 torchcrepe ∩ praat-ac 一致帧（两个不同算法族，±50 音分）
作锚点，取 `offset = anchor_cents − 20·bin` 分布的**主模态**。

**这里踩过一个坑，值得单独记**：第一版用 `np.polyfit` 拟合，得到斜率 16.4、
残差 322 音分。原因是八度错是 ±1200 音分的离群点，最小二乘会被整体拖走。
换成主模态后 IQR 只有 **10.9–11.0 音分**，八度簇自然分离（各占 0.4% / 1.0%）。

**mel 配置的评分因此不看拟合残差，看 offset 主模态的紧致度：**

| 配置 | 截距 | IQR | 峰值 | 八度错 |
|---|---|---|---|---|
| **power=2 htk=1 norm=slaney fmin=30** | **1998.6** | **11.0** | **0.572** | **4.6%** |
| power=2 htk=1 norm=none fmin=30 | 1998.1 | 11.0 | 0.554 | 4.9% |
| power=1 htk=0 norm=slaney fmin=30（=约定值） | 2569.9 | 50.6 | 0.288 | 1.0% |
| power=2 htk=1 norm=slaney fmin=0 | 1842.3 | 99.3 | 0.384 | 3.2% |

**证据 3 · 合成正弦的绝对真值** —— 独立佐证，不参与定参

标定完成后回头测（`RmvpeEstimator.self_check()`）：

| 真值 | 测得 | 误差 |
|---|---|---|
| 98.00 Hz | 97.87 | −2.33 音分 |
| 220.00 Hz | 219.46 | −4.23 音分 |
| 440.00 Hz | 440.19 | +0.74 音分 |
| 880.00 Hz | 880.43 | +0.85 音分 |

**8/8 落在 ±4.3 音分内**，全部 100% 有声。线性 chirp 200→600Hz：误差中位 +3.03 音分、
|误差| 90 分位 11.90 音分。三条证据链互相印证。

## 采用的参数

```python
MEL = dict(n_fft=1024, win_length=1024, hop_length=160, n_mels=128,
           fmin=30.0, fmax=8000.0, clamp=1e-5,
           power=2, htk=True, norm="slaney")     # ← 这三个是实测定的
CENTS_PER_BIN = 20.0                # 重采样法 20.202 ± 0.130
CENTS_BASE    = 1997.3796077132352  # 稳健标定 1998.6，差 +1.2 音分
前向          = up_first / channel_major / time_rows
```

## 这条决策没有解决的问题

- **截距借了 torchcrepe ∩ praat-ac。** 只借了一个标量，且 RMVPE 的音高**判决**
  （选哪个 bin）完全独立，但绝对轴的零点是共享的。合成正弦把它独立佐证到
  ±4.3 音分，算是补上了，但要记着这层依赖存在。
- **`norm=slaney` vs `norm=none` 没有分出胜负**（IQR 都是 11.0）。取 slaney 是因为
  八度错率略低（4.6% vs 4.9%）、置信略高。这个选择证据不强。
- 截距实测 1998.6 与约定 1997.38 差 1.2 音分。差得小，但不为零，说明前端可能
  还有一处极小的不一致。1.2 音分远低于 50 音分的判据，不影响使用。

## 什么证据会推翻这条决策

- 找到 RMVPE 的原始训练代码，其 mel 前端明确是 Slaney 刻度 —— 那么这里 `htk=True`
  能对上正弦只是巧合，需要重新找真因（但正弦误差 ±4.3 音分很难是巧合）。
- 换一份素材（不同歌手、不同混音）后，同样的标定流程解出显著不同的截距 ——
  说明标定过拟合到了这一首，前端参数需要按素材自适应，那是个更糟的世界。
- 合成正弦在 900–1200 Hz（本曲没用到但和声可能到）出现系统性偏差 ——
  说明标定只在测过的 98–880 Hz 有效。
