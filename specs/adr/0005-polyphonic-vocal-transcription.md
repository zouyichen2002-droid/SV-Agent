# ADR-0005 — 线 1 重定义为多声部人声转写；分离回到关键路径

| | |
|---|---|
| 状态 | **已接受**（用户直接给出目标与路线） |
| 日期 | 2026-08-22 |
| 决策者 | 用户 |
| 影响范围 | 线 1 的全部；**取代 ADR-0002**；使 ADR-0004 的八度抑制规则待重审 |

## 背景：目标变了

此前（交接文件 + ADR-0001..0004）的线 1 目标是：
**从参考干声反推一条可唱的主唱轨**。所有实现都建立在「每一帧只有一个音高」上。

用户给出的真实目标是：

> 工程里的轨 3 是原唱（洛天依）的人声轨，**里面含主旋律 + 多个和声声部**。
> 把它拆成 **1 条主旋律 + N 条次要和声轨**，类似 SynthV 自带的音符识别，
> 但要更准 —— 因为我们已经有歌词和对应时间。
> SynthV 自带的主要问题是**有和声时把两个以上的声音识别成一个声**。

工程现状（用户截图）也与交接文件 §4.4 记的 7 条轨完全不同，那张表已过期：

| 轨 | 内容 |
|---|---|
| 1 | `SV自动识别音符_主旋律…`（星尘）—— SynthV 自带识别的产物 |
| 2 | `伴奏` / `no_vocals` |
| 3 | **`vocal_洛天依（和声，多…）` / `vocals` —— 参考音轨** |
| 4 | `SV自识别音符_次要和声`（星尘）—— SynthV 自带识别的产物 |

## 这个重定义推翻了什么

### 取代 ADR-0002（起手点选阶段 1 而非阶段 0）

ADR-0002 把 stem 分离降级，理由是实测「分离做到完美最多解决 26% 的音高证据缺口」。
**那个测量的前提是「只要主唱」。** 目标改成「要主旋律 + 每一条和声」之后，
分离不再是可选的预处理，**它就是交付物本身**。

ADR-0002 的测量本身没错（在它自己的问题设定下成立），错的是问题设定。
状态改为「已被取代」，不删。

### ADR-0004 的八度抑制规则待重审

ADR-0004 引入 `required=["rmvpe"]`，理由是「crepe+praat 单独联署的 4.8% 帧里，
rmvpe 有值时 79% 差整一个八度」，把那批当假确认剔掉了。

**在多声部素材上，两个估计器报相差一个八度可能都对 —— 它们各自跟对了一个声部。**
被剔掉的可能是信号而不是噪声。这条要在拿到分离 stem 之后重测：
如果那 4.8% 的帧里，crepe 的读数对应和声 stem、rmvpe 的读数对应主唱 stem，
那 ADR-0004 就选错了。

## 复音程度：两次测量都失败，如实记录

动手前想先测「这条音轨到底有多少比例是多声部」，两条路都不可用：

| 方法 | 结果 | 为什么不可信 |
|---|---|---|
| RMVPE 显著图多峰 | 演唱帧 **4.6%** 有 ≥2 峰 | RMVPE 在**单声部**歌声上训练，设计目标就是压掉除一个声部外的一切。拿单声部检测器找复音，得到的是被严重压低的下界 |
| 自实现谐波求和 | 演唱帧 **100.0%** 有 ≥2 峰 | 检测器饱和，等于没说。次谐波抑制太弱（只处理 /2、/3 且只减 0.5×），谐波分量与共振峰都被当成峰。两条证据 Jaccard 0.046 |

**从头写多音高估计器不是一个短活**，实测证明。这条路放弃。

唯一站得住的旁证：RMVPE 次峰的音程分布里，**八度占 55.9%、纯五占 11.5%**，
而这两个音程恰好与泛音无法区分；非谐波关系音程（二度/三度/六度）合计只有 197 帧。
即便当作下界，它看到的第二声部也大多落在八度/五度上 ——
与 `benchmark-facts-chaosheng.md` §4.2 记的「和声在主唱上方八度」一致。

## 决策：分离优先 + 独立裁判

**用户选的路线**：先分离成独立 stem，再用**已标定**的单声部估计器逐条做 f0。
把一个难的多音高问题变成 N 个已验证的单声部问题，复用 ADR-0003 全部成果。

两级分离，误差会累积，必须记账：

```
原始混音 ──Demucs──> vocals（工程轨 3，含主旋律+和声）
                        └──karaoke 模型──> 主唱  +  和声/伴唱
```

**karaoke 模型的输出命名有坑**：它的 `vocals` = 主唱，`instrumental` = 和声/伴唱，
不是「人声/伴奏」。

### 刻意跑多个不同架构的分离器

分离结果不能用分离器自己验。选架构不同的两个：

| 模型 | 架构 | vocals SDR |
|---|---|---|
| `mel_band_roformer_karaoke_gabox.ckpt` | Transformer | 8.69 |
| `UVR_MDXNET_KARA_2.onnx` | ONNX 卷积 | 5.43 |

两者若在同一时段给出一致的主唱/和声划分，可信度远高于单模型。

### basic-pitch 装不上 —— 独立裁判改用别的

用户批准的路线里包含「basic-pitch 交叉验证」。**实测装不上**：
Python 3.13 下构建失败（其构建链用了 3.12 已移除的 `pkgutil.ImpImporter`），
`--only-binary :all:` 也解不开依赖。0.4.0 及以下全部如此。

替代的独立裁判设计（不依赖任何单一分离器）：

1. **两个不同架构的分离器**各自出 主唱/和声 stem
2. 每条 stem 上跑已标定的 RMVPE + CREPE（单声部，已验证）
3. **回代检验**：把两条 stem 各自的 f0 拿回**原始混合 stem** 的 RMVPE 显著图上查，
   两个音高是否都对应到显著图上的实际峰。若某个声部的 f0 在混合信号里找不到
   对应峰，说明那是分离器造出来的，不是原本存在的声音

第 3 条是关键：它用**混合信号本身**当裁判，不依赖分离器的判决。

仍待选项：直接拿 basic-pitch 的 ONNX 权重自己写推理（与 ADR-0003 对 RMVPE 做的
是同一类工作）。成本不低，暂不做，留作 ADR-0004 重审时的备选裁判。

## 歌词分配

歌词只覆盖主唱 + 9 个括号和声行；**没标括号的和声声部没有文本**。

**用户拍板：和声沿用主旋律同位置的字**（同音和声，流行编写里最常见）。

风险要记：若实际是拖长元音、或和声唱的词与主唱不同，字就错了。
拿到和声 stem 后应人工试听抽查这个假设。

## 什么证据会推翻这条决策

- 两个 karaoke 模型对主唱/和声的划分互相不一致（Jaccard 低），
  且回代检验显示两者都造出了混合信号里不存在的峰 ——
  说明这份素材的和声与主唱在频谱上不可分，应回退到
  「人按耳朵摆音符 + agent 做调声」（交接文件 §10 的回退路径）。
- 分离后的和声 stem 里同时仍有 2 个以上声部（三声和声），
  单声部 f0 照样不够 —— 那就需要递归分离或真正的多音高模型。
- 和声实际唱的不是主唱的字 —— 歌词分配决策要改。
