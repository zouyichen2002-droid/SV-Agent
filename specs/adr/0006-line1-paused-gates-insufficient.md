| | |
|---|---|
| 状态 | **已接受** |
| 日期 | 2026-08-22 |
| 决策者 | 用户（实听验收不通过，决定转向线 2） |
| 影响范围 | 线 1 全部；线 2 的门槛设计（**这条的教训必须带过去**） |

## 决策

**线 1 暂停。主线转到线 2（独立创作）。**

用户原话：「不行，验收失败。这样吧，先做创作部分的逻辑链，翻唱这个太难了。」

## 这次失败的真正信息

**不是「翻唱很难」。是「我设计的量化门槛全部通过，人耳仍然判否」。**

交付时的实测数字，逐条都过：

| 门槛 | 要求 | 实测 | |
|---|---|---|---|
| 阶段1 · 跨估计器一致率 | ≥85% | 87.4% | 过 |
| 阶段1 · 演唱行音高证据覆盖中位 | ≥65% | 70.3% | 过 |
| 阶段4 · 音符重叠 | 0 | 0 | 过 |
| 阶段4 · 最短时长 | ≥85ms | 90ms | 过 |
| 阶段4 · **虚构音符** | 0 | **0** | 过 |
| 阶段3 · 字级直接对齐 | ≥98% | 95.2% | 差 2.8 个百分点 |
| 歌词覆盖（带正确字的音符 / LRC 字数） | 未定门槛 | 87.0% | — |
| **人工验收** | 无可闻错位 | **不通过** | **否** |

对照上一次失败（交接文件 §5）：那次有 21% 的音符是从邻居抄的音高，
用户听到的「歌词错位」有明确根因。**这次虚构音符是 0，用户仍然判否。**
所以这次的问题不在"造假"，在别处 —— 而我的门槛集合**没有任何一项能预测它**。

### 门槛集合缺了什么（这是要带到线 2 的东西）

我的门槛全是**逐项局部指标**：单个音符的几何、单个字的对齐、单帧的音高一致。
它们对下面这些**整体性**的东西完全无感知：

1. **旋律的乐句完整性。** 一句里 87% 的字有音符、13% 没有 —— 局部看很好，
   但缺的那几个字会把乐句撕开。人听的是句子，不是音符。
   403 个音符里 129 个是拖腔 `-`，它们的分布是否自然，我一个指标都没测。
2. **音符序列的音乐合理性。** 我逐个音符验证音高有证据，但从没检查过
   相邻音符构成的音程是否成调、句末落音是否在和弦上、有没有大量不成调的半音。
   逐帧正确 ≠ 旋律正确。
3. **时间的听感对齐。** 我测的是「字起音 vs 音符起音」的距离分布（59% 在 ±85ms 内），
   但没测「整句相对伴奏的相位」。整句系统性早/晚 100ms 在逐字统计里几乎看不出来，
   耳朵却立刻听得出。阶段2 那个「首字偏移中位 −0.658s」的问题就是这一类，
   我是靠一个诊断指标偶然发现的，不是靠门槛拦住的。
4. **拖腔 `-` 的语义正确性。** 129 个承接音符，如果切在元音之外，唱出来就是断的。
   我没有任何检查。

**结论：局部指标全绿不代表整体可听。门槛体系需要至少一项"整体性"判据，
而这一项在自动转写里很可能只能是人耳。**

## 线 1 有哪些东西是站得住的（不要重做）

暂停不等于作废。下列结论有实测支撑，换任何素材都成立：

- **RMVPE 前端的实测标定**（ADR-0003）：mel 是 HTK 刻度不是 Slaney，
  按 Slaney 喂会静默偏低 570 音分。自检：合成正弦 8/8 在 ±4.3 音分内。
- **自实现的 CTC Viterbi 正确**：与 `torchaudio.functional.forced_align`
  起帧 29/29 完全相同。
- **karaoke 二级分离的可用性边界**：主唱 stem 的回代检验 91.4%、两个不同架构的
  分离器一致 97.0%；**和声 stem 只有 51.7%**，约一半是分离器幻觉。
- **回代检验这个方法本身**：把分离结果拿回原始混合信号的显著图上查是否有峰。
  它抓到了「和声 stem 一半是幻觉」，也暴露了自己的盲点（器乐渗漏在混合信号里
  是真实能量，照样通过）。
- **构建方向**：字定音符边界 >> 音高定边界再塞字（87.0% vs 65.3%）。
- 一整套踩过的坑：见 `specs/environment-notes.md`（5 条）。

## 什么证据会让线 1 重启

- 线 2 做起来之后，**门槛体系里补上了「整体性」判据**（例如乐句完整度、
  调性一致度、整句相位），拿它回头量线 1 的现有产出，能定位到具体是哪一类
  整体性缺陷 —— 那时线 1 值得重做一遍。
- 找到一份**主唱与和声本来就分轨**的素材（不需要分离），
  线 1 的难度会掉一个量级。《潮声回响》的难点很大程度来自二级分离。
- 用户的创作流程里出现「必须从音频反推音符」的真实需求（例如要翻唱一首
  没有 MIDI 的歌）。目前这个需求可以用「人按耳朵摆音符 + agent 调声」替代。
