| 影响范围 | 新增 `toolkit/svagent/dashboard.py` + `scripts/dashboard.py` + `tests/test_dashboard.py`；[建造顺序](../agent-architecture-v1.md#11-建造顺序)第 9 项的薄 CLI **位置不变** |

## 背景

第一版要不要做一个 Pi 式的命令行界面，还是做 `specs/testing-and-acceptance.md`
里那个单 HTML 仪表盘。

**这不是二选一。** Pi 的架构本身就是「一个库 + 多个前端」，
CLI 和仪表盘是同一个库的两张脸。真正的问题是**先长哪张脸**。

## 决定

**先做观察面（仪表盘），驱动面（薄 CLI）留在建造顺序第 9 项。**
同时立一条横切规则：**前端只渲染，不计算。**

## 为什么先观察面

**一、驱动面已经有了，观察面一个都没有。**
第一版创作者是对着 Claude Code 说话的 ——「副歌太平」是说给对话的。
这个对话就是当前的 CLI。再做一个命令行是在重做一个已经在用的界面；
而「它现在什么状态、刚才改了什么、能不能撤」目前零个界面，
全靠我打字告诉他。

这条在本项目有过教训：`fl_ping` 那次我连着两轮让创作者去改 FL 设置，
他的设置从头到尾是对的。**「我说过了」在这个项目里出过错。**

**二、有三样终端做不了，而它们恰好是核心。**

| | 为什么终端不行 |
|---|---|
| **点开就听** | 这是音乐项目，判据最终是耳朵。仪表盘能给每版旋律挂 `<audio>`，终端播不了。现状是给一串 wav 绝对路径让创作者自己去开 |
| **会话树** | §6.5 说树视图是「最常看的一屏」。分支 + 裁决 + 度量在终端里画出来很难看，而且滚上去就没了 |
| **改动高亮** | 哪几小节被改了，需要并排对照 |

**三、仪表盘能进 checkpoint，终端历史不能。**
可以回头打开「n06 那个节点当时长什么样」。这是会话树的直接延伸。

**四、创作者是全栈与 agent 的初学者。**
建造顺序第 1 项的验收判据全是「kill 掉看文件完不完整」这类**他看不见**的东西。
没有面板，他只能听我口头汇报。

## 驱动面赢在哪（说清楚，免得以后误以为它没用）

**它能接收输入，仪表盘不能。** 真正需要它的时刻是**第 10 项之后** ——
Mistral 当编排器，Claude Code 不在回路里了，agent 必须有自己的驱动面。
建造顺序把「库化 + 薄 CLI + 斜杠命令」放在第 9 项、第 10 项之前，
**这个位置本来就是对的，这次不动它。**

## 横切规则：前端只渲染，不计算

前端（仪表盘、将来的 CLI）里不许出现业务逻辑。
**需要一个新数字，去库里加，不在前端算。**

理由是 [ADR-0011](0011-drop-fl-bridge-from-v1.md) 记的那个 bug 模式：
`eval/line_offset.py` 和 `make_listening_checks.py` 各自组装同一条分析管线，
产出 0.340 和 0.360 两个数字，**两边都不报错**。
仪表盘要是自己算一遍指标，它和 `state.inspect()` 迟早对不上 ——
而且没有人会发现，因为没有人会去比对一个「只是显示」的界面。

落地时的第一个例子：进度条要「六步完成几步」，于是加了
`ProjectState.n_done`，而不是在渲染层 `sum(...)`。

**这条规则有自动判据**（`tests/test_dashboard.py::test_进度必须来自库_而不是前端自己数`）：
让库返回一个它自己绝对算不出来的数（99），前端照抄就对，自己算就露馅。
第一版这条测试写成「断言渲染出 2/6」，变异测试当场发现它根本不会响 ——
因为前端自己数出来也是 2。

## 代价

- 第一版仪表盘**只读**。点节点回滚需要服务器，那要等到有驱动面
- 观察面不能替创作者省下打字：所有操作仍然在对话里说
- 多一个前端就多一份要跟着状态模型改的东西

## 顺带发现的一件事

仪表盘建好当天就暴露了状态模型的一个缺失：**「被上游挡住」和「自己坏了」
在 `Step` 里是同一种东西**，于是「主旋律同轨重叠 57 处」和后面三步的
「等主旋律」被画成一模一样的红叉，看上去像三处出了问题。

补了 `Step.waits_for` 与 `Step.blocked_by_self`。
**修在库里，不在渲染层拿字符串猜** —— 这就是上面那条规则的用法。

这也正是先做观察面的收益：**看得见，才知道模型缺了什么。**

## 什么证据会推翻它

- 创作者实际使用时发现「要看的东西」都能塞进一屏文本，树和音频都用不上
- 第 10 项之后 Mistral 接管，发现对话式驱动完全不够用，需要提前做 CLI
- 仪表盘出现了「自己算一遍」的诱惑且无法用库解决（说明库的边界划错了）
