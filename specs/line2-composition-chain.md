# 线 2 · 独立创作的逻辑链

> 2026-08-22。线 1 暂停后转为主线，见 [ADR-0006](adr/0006-line1-paused-gates-insufficient.md)。
> 本文件是**设计**，不是已实现的东西。待决策项集中在文末 §7。

---

## 1. 线 2 为什么形状完全不同

线 1 是**反向工程**：从混合音频反推音符、音节边界、音高。所有难点都来自
「信息已经被混掉了，要把它还原」。

线 2 是**正向构造**：旋律是自己写的，歌词与音符的对应关系**从一开始就是已知的**。
上一轮那整类问题（分离、f0 估计、强制对齐、证据覆盖率）根本不存在。

剩下的活恰好全是桥已验证可用的：`add_notes` / `fit_lyrics` / `edit_notes` /
`add_pitch_controls`（Smart Pitch）/ `set_automation_points` /
`set_group_voice`（Vocal Mode）/ `humanize_notes` / `apply_expression_preset`，
和声用 `add_group_reference`（`create_harmony_track` 在 2.2.1 上会崩，已被上游禁用）。

## 2. 从线 1 迁移什么，不迁移什么

**迁移（已验证，直接用）**

| 资产 | 位置 |
|---|---|
| 桥的 MCP 客户端（JSON-RPC / contextId 语义 / grouping / 批量上限） | `toolkit/svchain/bridge.py` |
| 音符几何强制（0 重叠、时长边界） | `notes.enforce_geometry` |
| 配置化 + 阶段门槛机制 | `config.py`、`[gates.*]` |
| 可听对照的生成（左=参考、右=产出） | `scripts/make_*_checks.py` |
| ADR 纪律：选项 → 拍板 → 记录 → 什么证据会推翻 | `specs/adr/` |
| 五条环境坑（numpy LAPACK / librosa 漂移 / …） | `specs/environment-notes.md` |

**不迁移（线 2 用不到）**：分离、RMVPE/CREPE 的 f0 估计、CTC 强制对齐、
音高证据层。这些是「从音频反推」专用的。

**必须带过去的教训（ADR-0006）**：线 1 的门槛全是**逐项局部指标**，
全绿而人耳判否。线 2 的门槛必须包含**整体性**判据。

## 3. 线 2 的门槛怎么设：可程序化检查的音乐性约束

这是本设计的核心。中文歌里有几样东西是**能用代码硬性检查**的，
它们正好补上线 1 缺的那一类判据。

| 判据 | 怎么检查 | 为什么它是硬的 |
|---|---|---|
| **倒字** | `pypinyin` 取每字声调（1平 2升 3降升 4降 5轻），比对该字上的旋律走向。4 声（降）配上行大跳、2 声（升）配下行，都会让字听成别的字 | 中文特有，**唱出来是不是那个字**是客观的 |
| **音域** | 全部音符落在声库舒适音域内；超出的逐个列出 | 唱不上去就是唱不上去 |
| **字数 = 音符数** | 一字一音符（拖腔 `-` 除外），两者必须相等 | 定义级约束，不等就是错 |
| **句末落音** | 句尾音是否落在当前和弦的和弦音上 | 落在非和弦音上会「悬着」，是可判的 |
| **跳进** | 相邻音程超阈值（如大六度）标记；连续同向大跳加权 | 唱不动 / 不像旋律 |
| **调内音比例** | 全部音符落在调内音的比例（转调段单独标注） | 大量调外音 = 不成调 |
| **乐句完整度** | 每个乐句的音符是否连续、有没有中间缺口 | **线 1 缺的正是这一类** |

**倒字检查是这条线的差异化点**：它是中文歌词特有的、可自动化的、
而且和「LLM 写词」这件事天然耦合 —— 词和旋律必须一起改，不能分开优化。

## 4. 逻辑链

```
  A 立项与约束固化
      调性 / 拍号 / tempo / 曲式 / 目标时长 / 声库与舒适音域
      门槛：全部是显式数值，写进 song config
      ▼
  B 和声进行
      按曲式给每段一条进行；标注转调点
      门槛：进行在调内闭合；段落间的连接可解释
      ▼
  C 歌词        ← lyric-writing 技能
      门槛：字数符合曲式规划；押韵；**倒字风险分低于阈值**
      ▼
  D 旋律        ← composition-arrangement 技能
      门槛：音域内 / 字数=音符数 / 句末落音在和弦音 / 跳进受限 /
            调内音比例达标 / **倒字风险分复检**（词和旋律要一起过）
      ▼
  E 写入 SynthV  ← 桥（已验证零失败）
      add_track → add_notes(grouping=target) → fit_lyrics
      和声用 add_group_reference
      门槛：几何（0 重叠、≥85ms）+ 回读逐字段一致
      ▼
  F 调声
      Pit 曲线 / 参数自动化 / Vocal Mode / humanize / 表情预设
      门槛：**人工试听**（这是唯一的整体性判据，不可省）
```

C 和 D 之间是**双向的**：倒字冲突既可以改词也可以改旋律，
所以它们要作为一个联合优化环，不是流水线的两段。这是线 2 的编排难点，
也是「agent 编排」这个子系统最真实的载体。

## 5. 五个子系统在线 2 里的落点

交接文件 §1.1 要求五个子系统都有真实载体，**不要为了凑架构硬造用例**。
线 2 的落点比线 1 自然得多：

| 子系统 | 载体 |
|---|---|
| **MCP** | 消费桥（已有）**+ 自己写一个乐理/语料 server**：和弦进行库、韵脚检索、声库音域表、倒字规则表。自己写过 server 的面试信号强得多 |
| **Tool 设计** | 自己的工具面：`propose_melody` / `check_prosody`（倒字）/ `fit_lyrics_to_melody` / `apply_tuning`。每个都带守卫（音域、几何、倒字），撤销边界对齐桥的一命令一撤销 |
| **记忆** | 每首歌的工程状态与决策；**用户的调声惯例**（他偏好的 Pit 幅度、颤音起始、气声量）；历史否决过的方案 |
| **召回** | 四个已装技能（`synthv-tuning` / `composition-arrangement` / `lyric-writing` / `synthv-agent`）+ ADR 日志 + 历史工程。这是真语料，不是造的 |
| **编排 + eval** | §4 的分段门槛 + §3 的可程序化检查 + C↔D 的联合优化环 |

## 6. 第一步该做什么（我的建议）

**先做 §3 那张表里的检查器，不要先做生成。**

理由：生成部分有现成技能（`lyric-writing` / `composition-arrangement`），
LLM 写词写旋律是它的强项。而**检查器是这个项目独有的、也是线 1 失败教训的直接产物**。
先有检查器，生成的东西才有客观的接受/拒绝标准；反过来先做生成，
就又回到「让 LLM 写点东西然后人听」，没有工程含量。

具体地，第一个可交付：

```
输入：一段歌词 + 一条旋律（MIDI 或音符列表）+ 调性/和声进行
输出：一份逐项检查报告 —— 倒字风险逐字打分、音域越界、字数不匹配、
      句末落音、跳进、调内音比例、乐句缺口
再输出：可写入 SynthV 的音符（过几何门槛）
```

这东西**立刻可用**：他自己写的旋律也能拿来查。而且它是后面所有生成步骤的裁判。
