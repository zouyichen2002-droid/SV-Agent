## 一句话总结

从「宇宙无边无垠」这一个主题，到一个能播放的 SynthV 成品（人声 + 伴奏对齐），
全链路走通，**每一道关口的门槛都由创作者定、由他的耳朵判**。

## 三条被证据关掉的悬案

1. **ADR-0008「编排本身不行」** —— 消解。**确定性规则写得出能过耳的编排**：
   全部编排决定只有 13 行（`VOICING` 4 行定频段分配，`DENSITY` 9 行定段落起伏）。
   所以「引入生成模型出编排方案 + 用检查过滤」这条更重的路**暂时不需要**。
2. **ADR-0008「tick 精确 ≠ DAW 间对齐」** —— 消解。
   `.mid` → FL 导入 → FL 渲染 → SynthV 音频轨，四层之后偏移仍是 −1.6 ms。
3. **ADR-0006 的反例** —— 翻唱线上**所有量化门槛全过而耳朵说不行**。
   这次是反过来的：门槛全过，耳朵也说行。两次合起来才说明门槛集是**必要不充分**。

## 被检查抓出来、而不是被我发现的缺陷

这一节比上面的成功清单更重要 —— 它是「检查会响」的证据。

| 缺陷 | 谁抓到的 |
|---|---|
| 间奏和弦继承了副歌1 末句的 G，与曲式写的 Am 不符 | 六项校验的和弦音检查 |
| 垫顶音 C4(60) 与主歌2「向(60)/更(59)/深(60)」形成同音与半音打拍 | 六项校验的「不与旋律撞」检查 |
| 贝斯降八度在 F 和弦上变成 MIDI 29 = F1 = 43 Hz，只剩浑浊 | 声部音域打印 |
| `fl_ping` 假阴性：开桥后立刻 ping 必然 `alive=False` | 端口原始监听（我误判了用户两轮） |
| 体检拿到 `alive: False` 却打印「全部就绪」 | 用户配好之后的实测 |
| 对齐检测器有 **+12 ms 系统性偏置** | 正对照（拿样本级对齐的合成预览测） |

最后一条差点让创作者去修我自己的测量误差。**正/负对照是这条链上最便宜、
回报最高的一道工序**：负对照证明检查会响，正对照证明它的零点在哪。

## 诚实的缺口：这还不是 agent

**链路的下游一半（伴奏 → FL → 对齐 → 成品）是工程上扎实的**：确定性、可校验、
每一步都有会响的检查。

**上游一半（主题 → 词 → 旋律）目前是我手写的。** 检查只是安全网，不是生成器。
所以现在这套东西是「一个人 + 一堆脚本」，不是 agent。

要变成 agent，缺的正是 [ADR-0007](adr/0007-creator-agent-control-flow.md)
已经设计但**尚未实现**的控制流：

    发散 N 个候选 → 确定性过滤（七项检查）→ 创作者剪枝 → 否决记忆回流

其中「否决记忆」连设计都还没有：记录「他否决了 B」几乎没用，
有用的是**为什么**，而他往往说不出来。这是下一阶段最硬的问题。

其它已知缺口：

- **零自动化测试**（上游 `synthv-agent-bridge` 有 24 个测试文件）。
  敏感度测试目前只是命令行里临时跑的，没有固化。
- 门槛散落在各脚本里（`CheckCfg` / `GUIDE` / `OK_MS`+`WARN_MS`），没有统一定义。
- 七项检查里六项客观检查**只在这一首歌上跑过**。
- Mistral API 还没接。

## 复盘：FL 桥的混音层是闲置资本

2026-08-23 创作者关掉了混音支线（「test1 只是为了测试，已经不需要了」）。
把这条如实记下来，因为它指向一个**我推荐路线时的判断偏差**。

推荐 FL 路线时，我给的理由之一是「MCP 的 52 个工具里 18 个是混音/EQ/压缩/路由，
恰好强在我做不了的事上」。事后看这个理由**没有兑现**，原因有两层：

1. 工具数不等于可用能力。混音那 26 个工具全都要求**目标插件已经加载**，
   而 FL 脚本 API **不允许加载插件**（`fl_plugin_list` 原文：
   "We cannot load NEW plugins (FL API limit)"）。所以它们的前置条件
   是一串手动操作，而手动操作正是这个项目要消除的东西。
2. 我数的是 `@tool` 装饰器，没有实际启动服务问它。后来 stdio 实测是 67 个，
   而且发现了通用的 `fl_write_piano_roll_notes` —— 这两个数字都错过一次。

**真正交付价值的是**：确定性生成的 `.mid`（tick 级对齐）+ 我自己写的
`verify_alignment.py`（互相关 + 自校准）。两者都不需要 loopMIDI、不需要 MCP。

**loopMIDI 和 FL 桥现在是装好且验证可用、但没有用途的能力。**
留着不花钱，需要混音时直接可用。但不该把它算成这次的收益。

**下次的判据**：评估一个外部工具时，不要数它有多少工具，
要问「它的**前置条件**里有多少件仍然是手动的」。

## 复现这首歌

```bash
python E:\sv-bridge\out\melody_v2.py                    # 旋律 + 七项检查
python E:\sv-bridge\scripts\make_accompaniment.py       # 伴奏 MIDI + 预览
python E:\sv-bridge\scripts\verify_accompaniment.py     # 六项校验
python E:\sv-bridge\scripts\write_song.py --write       # 写进 SynthV（需桥在线）
python E:\sv-bridge\scripts\verify_alignment.py <FL渲染.wav>
```

手动的三件（都是工具能力边界，不是待办）：
SynthV 指派声库、FL 导入 MIDI 并挂音源、FL 导出音频。
前者是 SynthV 桥没有 `database` 字段，后两者是 **FL 脚本 API 不允许加载插件**。
