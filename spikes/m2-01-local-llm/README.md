## 测什么

只测以后真要用的事 —— **不让它凭一句话写旋律**（R03：旋律必须外部学习）：

| 项 | 怎么判 |
|---|---|
| 放不放得下 | 显卡 12 GB：几层上显卡、几层留 CPU；载入要多久 |
| 快不快 | 读提示、出字的速度（token/秒），关思考和开思考各一次 |
| 格式合不合 | 把 PRD 里 C01–C07 那张表转成 JSON，程序逐项核对编号和需求名（照抄才算对），最多试 3 次 |
| 中文好不好 | 一道歌词问题（什么是倒字），答案原样给你看 —— **不写进任何记忆** |

```bash
python probe_local.py
```

- 服务由脚本自己起、测完自己关，不留后台进程；只用 NVIDIA 那块显卡（集显慢），放不下的留 CPU（`--fit on` 自动分）
- 结果写在仓库外 `E:\sv-agent-data\probes\m2-01-local-llm\`
- 模型 `E:\sv-agent-data\models\llm\`；运行工具 `E:\sv-agent-data\tools\llama.cpp-b11259\`

## 结果（09-29，Vulkan 版，上下文 8192）

| 项 | 结果 |
|---|---|
| 载入 | 21.3 秒；服务测完自己关了 |
| 出字速度 | **约 5.6 token/秒**（关思考、开思考都一样） |
| 读提示速度 | 短提示 58 token/秒；434 token 的提示只有 **8.9 token/秒**（读了 49 秒） |
| 开思考 | 想了 4328 个字、到 3000 token 上限被截断，**没给出答案**，用了约 9 分钟 |
| JSON | **一次就对**：7 项编号和需求名逐字照抄，程序核对通过 |
| 中文问答 | 「倒字」的解释对；但第一个例子是错的 —— 说《晴天》「从前」会听成「从钱」，「前」「钱」同音同调，不是倒字 |

**结论：能用、格式守得住，但在这台机器上太慢。** 模型 14.3 GB 放不进 12 GB 显存，有一部分在 CPU 上算。
内容会一本正经地举错例子 —— 这和换不换本地无关，要靠检查兜底（Mistral 也一样）。

提速的路（都要下载，先问）：CUDA 版运行工具（GPU 读提示快得多）· 更小的量化版整个放进显存 · 换成每次只算 3B 的 MoE 模型。

### 09-29 换 CUDA 版再测（你说「可以换 CUDA 版试试」）

| 配置 | 载入 | 读提示（434 token） | 出字 · 中文问答 | 出字 · JSON | JSON 一次就对 |
|---|---|---|---|---|---|
| Vulkan，上下文 8192 | 21.3 秒 | 8.9 /秒 | 5.5 /秒 | 5.7 /秒 | 是 |
| **CUDA 13.4**，上下文 8192 | 12.2 秒 | 376 /秒 | 7.9 /秒 | 7.4 /秒 | 是 |
| CUDA + 上下文 4096 + KV 缓存 8 位 | 8.7 秒 | 419 /秒 | 8.1 /秒 | 7.9 /秒 | 是 |
| 再加 MTP 推测解码（模型自带的草稿层，不用另下） | 9.2 秒 | 352 /秒 | 6.1 /秒（猜中 33%） | **11.1 /秒**（猜中 89%） | 是 |

- **CUDA 解决了读提示**（快 40 多倍）；**出字卡在 8 左右**：14.3 GB 放不进约 11 GB 的空闲显存，约四分之一的层在 CPU 上算，
  腾出缓存只多装得下一两层
- MTP 对格式固定的输出有用（JSON +40%），对自由发挥的中文反而慢 —— 只在要 JSON 的活里开
- 开思考：CUDA 版也是想到 3000 token 上限都没答完 —— 这台机器上本地模型**别开思考**
- 中文问答两次都举错例子（把同调的字当倒字、「我」标成阳平）—— 乐理和字音这类知识靠不住，要检查兜底

**要再快只剩两条路**（都要下载）：同一个模型的更小版本整个放进显存（UD-Q2_K_XL 9.83 GB / UD-IQ3_XXS 10.93 GB，质量降一些）·
换每次只算 3B 的 Qwen3.5-35B-A3B（17.5 GB，旧半年）。
