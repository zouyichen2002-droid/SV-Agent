## 09-29 第二步：C02「拍子必须算对」—— `grid_check.py`

创作者 09-29 定：翻唱不做乐器 MIDI，**但拍子要算对**（创作时可能要往里加乐器）。PRD C02 的线：速度、拍点、小节线，网格对真实拍点整首偏差 ≤ ±20 ms。

**更正第一步的一句话**：SynthV 存的 `beatLocations` 是一张**均匀网格**（196 个拍点离直线 0.000 ms）—— 就是一个速度加第一拍，
不是逐拍测的。第一步报告里「整首几乎不飘」不是证据：均匀网格本来就不会飘。准不准只能拿别的东西量。

| 裁判 | 做法 |
|---|---|
| 零点 | Suno 的 5 条乐器分轨加起来，和 SynthV 分析的那条伴奏做互相关 —— 必须是同一个零点 |
| 速度 | 每条分轨的起音强度曲线按网格的**十六分**折起来，每 15 秒一段；比「错的速度」（差 3–6%）折出来的高 4 个标准差才算锁住；锁住的段偏差前后都在线内 → 这一段速度对。结尾再用 8 秒窗细到 2 秒一格 |
| 小节线 | 每拍的底鼓、军鼓高频（鼓分轨分频段）和换和弦（键盘 + 贝斯的色度）按「8 拍里的位置」汇总：换和弦最多的那一位是「1」，底鼓要同意；逐小节看，连着两个以上小节换和弦都挪到同一拍 → 灰 |
| 耳朵 | 两份带节拍器的试听（132 一拍 / 66 一拍，「1」那一下高而响），创作者听 |

**试过、不能用的量法**（自检里都补了对应的注入）：
- 先挑离散起音、只看落在网格线附近的、取中位数 → 在对称的窗口里乱撒，中位数本来就在 0 附近；键盘、贝斯起音软，挑出来的一大半是乱的。探路时靠它得出「五条分轨都在 ±12 ms 以内」，**是错的**
- 按八分或按拍折 → 十六分位置的起音正好在线和线中间，把压线的抵消掉（造的 120 BPM 十六分被扫成 113.85）

结果（《傍晚》，`E:\sv-agent-data\probes\m5-00-beat-grid\grid_check.json`）：
- 零点：分轨比伴奏晚 0.000 ms（相关 0.865）
- **0–2:24 恒定 131.9775 BPM**（SynthV 的数，= 65.98875 × 2）：键盘每 15 秒一段都锁住，偏差 −3 ~ +16 ms；鼓 −6、−7 ms，贝斯 −2 ms；
  每 8 秒窗自己扫出来的速度 131.6–132.1
- 对照：Suno Studio 显示 **4/4、131 BPM**（创作者 09-29 看的）。4/4 和小节线对上；131 只在尾声那段对得上 —— 从同一个「1」起，0:15 晚 112 ms（一个十六分）、0:30 晚半拍、1:00 晚一拍、2:24 晚 2.4 拍（`click_compare.py`，另有一份 131 的对照试听）。整数 132 在这 2 分 24 秒里也还在线内，但 1:00 早 10 ms、2:24 早 25 ms
- **小节线**：「1」= SynthV 第一拍（0.1039 s），之后每 4 拍（按 132）/ 每 8 拍（按 66）一小节；
  鼓：底鼓每个 66 拍都打、军鼓在 66 的第 2、4 拍 —— 按 66 是常规的「军鼓 2、4」，按 132 是「军鼓只在第 3 拍」的半拍感
- **2:24 以后（尾声）锁不住**：每 8 秒窗扫出来 110–131 乱跳、整体偏慢；2:31–2:46 换和弦一路从第 2 拍挪到第 3 拍 —— 灰
- 合成器、弦乐以长音为主，一段都锁不住，当不了裁判
- 两份试听的节拍器只响到 2:24；从节拍器轨反测的拍点和网格最多差 0.30 ms

```bash
cd /e/sv-bridge/spikes/m5-00-beat-grid && python grid_check.py
```

## 09-30 第二首《潮声回响》：没有 Suno 分轨、中途变速 —— `beat_song.py`、`tempo_map.py`

没有 Suno 那种一条条的分轨（只有 Demucs 分的人声 / 无人声），裁判改成：伴奏整条 + HPSS 拆出来的打击部分、和声部分（和声再低通当贝斯）+ 人声。
量法全用 grid_check 的。改了两处（《傍晚》的结果逐项核过，一模一样）：
- 偶然水平用的「错的速度」按歌的速度缩放（`null_for`）：按 132 定的 124–140 里有 129 = 86 × 3/2，会碰上真速度的倍数
- 「每一窗自己最合的速度」扫的范围跟着歌的速度（默认 96–140 是《傍晚》那档，86 BPM 的歌会被扫成 129）

`beat_song.py`（一个速度的歌）：候选 = SynthV 的节拍分析 + 配置里给的；另外在候选附近按数据细扫速度和相位，锁住的段不比候选短就用细扫的。

`tempo_map.py`（中途变速的歌）：
1. 全曲 8 秒窗每 2 秒扫一次速度；连着 ≥ 4 个窗在 ±0.4 BPM 以内 = 一段
2. 每段细扫速度和十六分相位；**「1」在一小节 16 个十六分里找**：换和弦（和声部分色度）+ 底鼓（打击部分低频）最集中的那格。
   按拍折的方向不行 —— 打击乐八分、十六分铺满时方向离哪格都远；某一项 16 格几乎一样就不参与（标准化会把噪声放大）
3. 每段按小节往前、往后扩（以小节线开头的 8 秒窗还锁得住）
4. 相邻两段：交界附近两串小节线最近的一对差 ≤ 20 ms → 在那条小节线上换速度（编曲软件都是这么换的）；接不上的中间算自由
5. 速度表：前奏拉成整数个小节；每两个换速度点之间整数个小节；尾声自由
- 自检：造的「自由前奏 + 82 BPM + 在小节线上换 86」要认出两段、「1」、交界、自由前奏，速度表的拍和真拍差 ≤ 15 ms
  （造的声音过起音强度曲线会晚约 9 ms）；注入「后一段小节线挪 60 ms」不许认成接上

《潮声回响》结果（`E:\sv-agent-data\probes\m5-00-beat-grid\潮声回响\tempo_map.json`）：
- SynthV 的 85.84 不对（只在 45–75 s 锁住、偏差一段一段挪）；v1（08-20）说的「全曲 86」只对中间那段
- **前奏 0–20.9 s 自由 → 82.02（到 56.03 s）→ 86.00（到 176.04 s）→ 81.97（到 202.4 s）→ 尾声自由**；
  两处换速度：两段各自推到交界，小节线差 3.0 ms、0.9 ms；每段整数个小节（13、43）
- 「1」：三段各自在 16 格里找，第一名都比第二名高一倍左右；按速度表回头量，三段都锁住（打击部分 −8 ~ +3 ms）
